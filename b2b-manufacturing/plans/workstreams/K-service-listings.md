## Design
`design/malva/specs/plp.md`. Routes `/[locale]/plumbing` and `/[locale]/waste-management` (Q-014), statically rendered with ISR; the sector filter reads `searchParams` and therefore is the **only** dynamic aspect: implement it as a client component calling `GET /api/services?category=…&sector=…` **or** as a static page per sector via `generateStaticParams` — **use the static-per-sector approach** (`/plumbing?sector=healthcare` is rewritten to a static segment `/plumbing/sector/healthcare` by `next.config` rewrites, keeping the public URL) so the page stays cacheable; if this proves impractical record it in `PROJECT-FINDINGS.md` and ask (Q-K-1).
- `PageHeader` (breadcrumb `Home / Plumbing`, H1, lead from the design), grid of `ServiceCard` (3 columns, gap 24 px) in `display-order`, each card **one link** whose accessible name is the service name (number `aria-hidden`), supporting band (plumbing: "How planned maintenance works" with 4 checks and image slot `cctv-survey`; waste: dark "Compliance, documented" with 2×3 checks), `CtaBand`.
- Sector control: chip row, shown only when ≥ 2 sectors would yield different results; active filter shown and removable; no-match state text from the spec; same URL reproduces the result.
- Empty category: header remains, body "No services are listed here yet." + Request a quote.
- Data from `getServicesByCategory` (G); unpublished services are absent and numbering stays continuous.
- Titles/descriptions unique; breadcrumb with `aria-current="page"`.
