## Design
Screens `/[locale]/account/sites` and `/[locale]/account/team`.
- **Sites** = the company's addresses (Business Unit `addresses`, with a label and a site contact name/phone in the address custom fields or `additionalAddressInfo`); an administrator (`UpdateBusinessUnitDetails`) adds, edits, removes addresses and chooses a default shipping address. Removing an address used by an open Quote Request is refused with an explanation. Uses `asAssociate(session).businessUnits()` (My Business Units API where it suffices).
- **Team** = the associates with role names (Admin = `mpw-admin`, Site contact, Finance). Administrators (`UpdateAssociates`) can **create a colleague** (name, work email, role): because no email exists (Q-022) the colleague's customer is created server-side with a one-time password shown **once** on screen and `mustChangePassword` flag (custom field) forcing a change at first sign-in; add the associate to the Business Unit through the provisioning client (My BU API cannot assign associates). Change role, remove associate. Site-scoped roles: a Site contact only sees data of assigned sites if Divisions are used — v1 keeps one Company unit (no Divisions) and documents it (IDEAS).
- **Last administrator rule:** removing or demoting the only `mpw-admin` is refused with an explanation (also when they try it on themselves).
- Permission gating: pages show read-only for roles without the permission; controls absent, API refuses.
