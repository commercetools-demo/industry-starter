## Design
Server tier built as `bootstrap-malva-storefront/specs/malva-bff-and-session` and `design.md` decisions 3, 5, 6, 8, 9.
- `lib/env.ts`: pure `validateEnv(env)` returning the typed config or throwing an `Error` that names the missing variable (`CTP_PROJECT_KEY, CTP_AUTH_URL, CTP_API_URL, CTP_CLIENT_ID, CTP_CLIENT_SECRET, CTP_SCOPES, CTP_DEFAULT_STORE_KEY`); a second `validateProvisioningEnv(env)` for `CTP_PROV_*`. `instrumentation.ts` calls both at server start (provisioning only when present or in production).
- `lib/ct/client.ts`: **the only place `new ClientBuilder(` appears.** One internal `buildRoot(config)`; exports `apiRoot` (Frontend client) and `provisioningRoot` (narrow server-only client, used only by F/N). `withClientCredentialsFlow`, `withHttpMiddleware`, `createApiBuilderFromCtpClient(...).withProjectKey(...)`.
- `lib/session.ts` (+ pure `lib/session-core.ts` for sign/verify): jose HS256 token in cookie `malva_session`, HTTP-only, `SameSite=Lax`, `Secure` outside local dev, `path=/`, 30 days. `Session` type fields exactly as the spec lists (customer id/email/name, `cartId`, business-context fields, locale triple). `SESSION_SECRET` missing or < 32 chars throws at import except when `NODE_ENV==='test'`; **no fallback key**. Tampered or expired → empty anonymous session. Helpers `getSession()`, `updateSession(patch)` (all-or-nothing write; never a partial cookie on error).
- `lib/api.ts`: `handle(fn)` wraps a Route Handler body, maps SDK errors to a safe `{ error }` with a status (never the raw error, request body or credentials); `requireCustomer(session)` → 401 before any commercetools call; `requireBusinessUnit(session)` → 400 "No active business unit".
- `lib/types.ts` (app types, grows), `lib/mappers/index.ts` skeleton; mappers use `getLocalizedString`.
- `app/api/health/route.ts` (dev only): `apiRoot.get()` → `{ ok: true, projectKey }`; 404 in production; `scripts/check-no-health-in-release.mjs` fails a release build containing it (G adds the search-indexing report).
- `.env.example` scope list: start from the Frontend API client B2B template; **every scope beyond the template carries a reason comment**; `lib/scopes.test.ts` asserts each scope in `.env.example` has a comment.
