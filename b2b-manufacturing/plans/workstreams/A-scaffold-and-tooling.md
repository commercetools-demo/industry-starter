## Design
Build exactly what `openspec/changes/bootstrap-malva-storefront/design.md` describes (target layout, decisions 1–4, 11, 15). The app lives in `b2b-manufacturing/site/`; the seed package `seed/` is separate (D14) and must not be touched here.
- Scaffold with the skill command `/nextjs-setup-project` (`create-next-app@^16 --app --typescript --tailwind=false`, then Tailwind v4 via `@tailwindcss/postcss`, next-intl `^4`, `swr`, `jose`, `server-only`, SDK `@commercetools/platform-sdk@^8` and `@commercetools/ts-client@^4`, Vitest + Testing Library + jsdom, ESLint). If the command asks about existing files, `site/` must be empty: **scaffold first, then add anything else.**
- `npm run check` = `tsc --noEmit && eslint . && node scripts/check-versions.mjs && node scripts/check-secrets.mjs && node scripts/check-server-only.mjs && vitest run`. `npm run build` is separate; the build fails on type errors.
- Lint rules (ESLint flat config, `no-restricted-imports` + overrides): files with `'use client'` or under `components/`, `hooks/` may not import `@/lib/ct/*` or `@/lib/session`; `@commercetools/platform-sdk` only inside `lib/ct/**` and `lib/mappers/**`; `next/link` and `redirect` from `next/navigation` banned in `app/[locale]/**` and `components/**`; a custom rule or `no-restricted-syntax` for `fetch(` with a commercetools host. Each rule has a fixture file under `eslint/fixtures/` and a test that runs the ESLint Node API and expects the message.
- `.env.example` lists `CTP_PROJECT_KEY, CTP_AUTH_URL, CTP_API_URL, CTP_CLIENT_ID, CTP_CLIENT_SECRET, CTP_SCOPES, CTP_DEFAULT_STORE_KEY, CTP_PROV_CLIENT_ID, CTP_PROV_CLIENT_SECRET, CTP_PROV_SCOPES, SESSION_SECRET` with **no values** and a comment per line.
