# Workstream N — Registration and sign-in

**Depends on:** D, F, H
**Implements:** malva-client-portal[Open registration; Client sign-in]
**Skills:** commercetools-storefront (`b2b/customer-auth.md`, `core/customer-auth.md`), commercetools-commerce-patterns (Business Unit and associate model)

## Design
`design/malva/specs/account.md` and the Open registration / Client sign-in requirements. No email (Q-003): accounts auto-verify.
- `lib/ct/auth.ts`: `loginCustomer(email, password)` uses **`apiRoot.login().post()`** (never `customers().login()`); anonymous cart merge: pass the session `cartId` as `anonymousCart` with `anonymousCartSignInMode: MergeWithExistingCustomerCart` so the quote list survives sign-in (P relies on it).
- `lib/ct/registration.ts` `registerCompany(input)`: validates, then in this order: create the Customer (`isEmailVerified: true`, custom type `mpw-customer` with `jobTitle`, `phone`) with the Frontend client → create the Company Business Unit with **`provisioningRoot`** (`unitType: Company`, key `mpw-<slug>-<random4>`, name, status `Active`, `stores: [mpw-web]`, `associates: [{ customer, associateRoleAssignments: [{ associateRole: { key: 'mpw-admin' } }] }]`, custom type `mpw-company` with `sector`) → return ids. **Compensation:** if the BU step fails, delete the just-created customer; never leave a half-created account (spec: "no account left half-created"). Idempotency key = email; a second concurrent call for the same email creates nothing.
- Duplicate email: no account created, generic message offering sign-in; the attempt counts toward the rate limit (U adds the shared limiter; here use an in-memory per-IP limiter interface `RateLimiter` with a test double).
- Password rules: ≥ 10 characters and not in `lib/common-passwords.ts` (embedded list of 1000). Errors name the rule.
- Routes: `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/logout` (clears per F), `GET /api/auth/me` (session fields → `{ customer, businessUnitKey }`). There is **no** password-reset route (Q-023).
- UI: Sign-in `Dialog` (opened by the top-bar/nav/footer buttons; focus on email; Escape/backdrop close; focus returns), `/[locale]/account/sign-in` page (deep links; return path `?next=` validated to a same-site path), `/[locale]/account/register` page (company name, sector, name, job title, work email, phone, password), links between them. No "Forgot password" link anywhere. `useAccount` hook (G) becomes real.
- Return path: visitor following a portal link while signed out is sent to sign-in, then back.
