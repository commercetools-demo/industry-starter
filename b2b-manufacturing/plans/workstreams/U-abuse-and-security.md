## Design
Open registration plus an anonymous request path invite abuse. Finish and prove:
- **Rate limiting**: replace N's in-memory limiter with a durable one that works across serverless instances (Netlify): `lib/rate-limit.ts` with an interface `RateLimiter.hit(key, { limit, windowSec })` and a Custom-Object-backed implementation (`mpw-ratelimit` container, key `<route>.<sha256(ip)>`, optimistic concurrency) — **IPs are hashed**, never stored raw. Limits: register 5 / hour / IP, login 10 / 10 min / IP+email, reset 5 / hour / IP, quote request 10 / hour / user. Over the limit → 429 with a generic message and `Retry-After`.
- **Honeypot + timing**: hidden field and minimum fill time on register and request forms; failing either returns the generic success-looking error without creating anything.
- **Security headers** (`next.config.ts headers()`): `Content-Security-Policy` (self + the image hosts in `content/images`), `X-Content-Type-Options`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`, `X-Frame-Options: DENY`/`frame-ancestors 'none'`; HSTS is set by the host.
- **Input safety**: server-side validation (zod) of every Route Handler body, length limits, no HTML rendering of user text (React escapes; assert no `dangerouslySetInnerHTML` except JSON-LD with a test), `next` return-path allow-list.
- **Secrets**: `scripts/check-bundle-secrets.mjs` greps `.next/static` for `CTP_*` values and the string `client_secret`; `npm audit --omit=dev` must have no high/critical (documented exceptions in `plans/notes/audit.md`).
- Review checklist `plans/notes/security-review.md` produced by Claude running the `security-review` skill on the branch.
