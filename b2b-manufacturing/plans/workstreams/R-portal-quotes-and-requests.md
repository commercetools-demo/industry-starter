# Workstream R — Portal: quotes and requests

**Depends on:** O, Q
**Implements:** malva-client-portal[Quotes and requests]
**Skills:** commercetools-storefront (`b2b/quotes.md`, `b2b/quote-actions.md`), commercetools-commerce-patterns (quote lifecycle)

## Design
Screen `/[locale]/account/quotes`. One list per Business Unit combining Quote Requests and issued Quotes (`b2b/quotes.md` unified thread pattern), each row: reference (`mpw-quote-request.reference`), created date (DD/MM/YYYY), services (names), site, status badge, actions. Statuses shown in plain words: Submitted, Being prepared (request accepted / staged quote in progress), Quote ready (Quote `Pending`), Accepted, Declined, Renegotiation requested, Cancelled.
- Data: `asAssociate(session).quoteRequests()` and `.quotes()` queries (BU-scoped; visibility needs `ViewMyQuoteRequests`/`ViewOthers…`, `ViewMyQuotes`/`ViewOthers…`); detail page shows lines (no prices until the seller issues a Quote; once a Quote exists its **prices are shown there** — this is the only place money is shown) and the seller comment (`Quote.sellerComment`, not the staged quote's, per the skill).
- Actions on a `Pending` Quote: **Accept** (`AcceptMyQuotes`/`AcceptOthersQuotes`; implemented as creating the order from the quote with `quoteStateToAccepted: true` when the role has `CreateMyOrdersFromMyQuotes`, else change state to Accepted), **Decline** (`DeclineMy…`), **Ask a question / renegotiate** (`RenegotiateMy…`, with a comment). Controls are **absent** when the role lacks the permission (Finance). State guards: only `Pending` quotes can be acted on; double-click cannot repeat an action (idempotent by state check, version conflict → refresh).
- Cancel a `Submitted` request (`MyQuoteRequestCancel`) if permitted.
- Overview block (O) "open quote requests" now reads from this module.
- Notifying the commercial team: none (no email); the team works from the Merchant Center.
