# Workstream V — Accessibility sweep

**Depends on:** J, L, M, P, Q, R, S, T
**Implements:** (none — cross-cutting; the prototype's defects are listed in `design/malva/DESIGN.md`)
**Skills:** commercetools-storefront

## Design
Target WCAG 2.2 AA. Fix the prototype defects by construction in H–T; this workstream **proves** it.
- Automated: `jest-axe` in every page/component test (from H), plus a script `scripts/axe-pages.mjs` that Claude runs against `npm run dev` through the browser for the page list in `plans/evidence/V/pages.md`.
- Manual-by-Claude keyboard pass: tab order, visible focus on every control, no keyboard trap except intentional dialogs, Escape and focus return on dialog and mobile menu, skip link, headings outline (one h1), landmarks, form labels and errors (`aria-describedby`, `aria-invalid`, live region), link purpose, reduced-motion respected, 200 % zoom and 320 px reflow, colour contrast (hero text on overlay, navy on white, white on navy, the `Sample content` tag, status badges which also use text).
- Known design risks to check explicitly: grey `--fg2` text on `--bg-muted`; hero H1 over photographs (overlay is 40 %); step badges; the sticky bottom bar on small screens not covering focused fields.
- Output: `plans/evidence/V/report.md` with every page, each issue, and its fix commit.
