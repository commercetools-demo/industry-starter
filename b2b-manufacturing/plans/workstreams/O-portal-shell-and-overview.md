**Depends on:** H, N

## Design
`design/malva/specs/account.md` (proposed screens, SO-02). Routes under `/[locale]/account/`.
- **Privacy:** `app/[locale]/account/layout.tsx` is a **dynamic** server layout that reads the session; no session → `redirect('/account/sign-in?next=…')` (outside any try/catch). Every portal page and API response sends `Cache-Control: no-store` (G config); portal data is never read through `unstable_cache`. A request for another company's resource returns **not-found** and discloses nothing (`requireOwnership(session, resource)` helper in `lib/ct/ownership.ts`, used by R, S, T).
- **Shell:** top bar + nav as the site, left sidebar 260 px: meta label "HELLO, {FIRST NAME}", items Overview, Service visits, Waste documents, Invoices, Quotes and requests, Sites, Team, Settings (Settings = profile + password change only). Company switcher at the top of the sidebar when the user has ≥ 2 Business Units (uses F's select route; switching rewrites the business-context fields atomically and clears every BU-keyed client cache).
- **Overview:** blocks: next scheduled visits (T), open quote requests (R), latest invoice (T), compliance alerts (T: expiring certificate, missed collection). For a client with no history each block shows a plain-language empty state; none errors. Until R/T land the blocks read from `PortalDataSource` stubs returning empty arrays.
- `lib/portal/data-source.ts`: `interface PortalDataSource { visits(bu), wasteDocs(bu), invoices(bu), alerts(bu) }`; implemented in T by custom objects.
- Settings: change name/phone/job title and password (login endpoint verifies current password).
