# Workstream F — Business-unit context

**Depends on:** D, E
**Implements:** malva-business-unit-context[Default public store and service selection; Store channel resolution; Atomic business-context session fields; Business Unit discovery at sign-in], malva-bff-and-session[Session lifecycle; Business-unit writes use the as-associate chain]
**Skills:** commercetools-storefront (`b2b/session-and-bu.md`, `b2b/customer-auth.md`), commercetools-commerce-patterns (Business Unit and store model)

## Design
As `bootstrap-malva-storefront/specs/malva-business-unit-context` and design decisions 7–8.
- `lib/ct/stores.ts`: `getStoreChannelData(storeKey)` → `{ storeId, supplyChannelId, distributionChannelId, productSelectionId }`, module-level `Map` cache, **failures not cached**, no partial data written to a session. `getDefaultStore()` reads `CTP_DEFAULT_STORE_KEY` (`mpw-web`) and throws a message naming the variable and key when the store does not exist.
- `lib/session.ts` additions: `initDefaultStore(session)` (anonymous sessions get the default store fields, no `businessUnitKey`); `setBusinessContext(patch)` writes `businessUnitKey, storeKey, storeId, distributionChannelId, supplyChannelId, productSelectionId` together or not at all; `setCustomer`, `setCart`, `clearCustomer` (drops customer fields, `cartId`, `businessUnitKey`; keeps locale and default-store fields), `clearCart` (after a quote request).
- `lib/ct/business-units.ts`: `getBusinessUnitsForAssociate(customerId)` using a **project-level** query (not the as-associate chain); `lib/ct/associate.ts`: `asAssociate(session)` returns `apiRoot.asAssociate().withAssociateIdValue({ associateId: session.customerId }).inBusinessUnitKeyWithBusinessUnitKeyValue({ businessUnitKey: session.businessUnitKey })`, and **throws** unless both ids are present. Every later cart/quote write uses it (spec: "Business-unit writes use the as-associate chain").
- Routes: `GET /api/business-units` (the user's units with their stores), `POST /api/business-units/select` (`{ businessUnitKey, storeKey }` → resolves channel data → `setBusinessContext`). Sign-in itself arrives in N; F delivers `signInSessionPatch(customer)` used by N: customer fields + first BU + its first store (default store if none).
- A customer with no BU: session has no `businessUnitKey`; BU-scoped endpoints answer 400 via `requireBusinessUnit`.
- Provisioning (creating a company) is **N's** task using `provisioningRoot`; F only supplies the store and role lookups it needs: `getAssociateRoleKeyAdmin()` constant `mpw-admin`.
