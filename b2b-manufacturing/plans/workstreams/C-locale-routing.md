## Design
Exactly as `bootstrap-malva-storefront/specs/malva-locale-routing`. Two launch locales `en-US` (US, USD) and `de-DE` (DE, EUR) (Q-012); default en-US, URL scheme from Q-014.
- `lib/utils.ts`: `COUNTRY_CONFIG = { 'en-US': { country: 'US', currency: 'USD', locale: 'en-US' }, 'de-DE': { country: 'DE', currency: 'EUR', locale: 'de-DE' } }`, `DEFAULT_LOCALE`, `getLocalizedString(field, locale)` (falls back to `en-US`, then first value, never throws), `formatMoney(centAmount, currencyCode, locale)` (kept for later use; services never call it, D21).
- `lib/ct/locale-validation.ts`: reads the project (countries, currencies, languages) through `unstable_cache(..., ['locale-validation'], { revalidate: 300 })` and returns only the entries the project supports.
- `i18n/routing.ts` (`defineRouting({ locales, defaultLocale: 'en-US', localePrefix: 'always' })`, `createNavigation`), `i18n/request.ts` (`getRequestConfig` loading `messages/<locale>.json`), `messages/en-US.json` (nav, footer, form labels grow with later workstreams; missing key fails the dev build).
- `proxy.ts` with matcher `['/((?!api|_next|favicon|.*\\..*).*)', '/']`: skips API, `_next`, files; passes already-prefixed paths; otherwise redirects to `/<locale>/…` using cookie `your-shop-country-locale` when valid, else default. Unsupported locale prefix → not-found page.
- `lib/locale-write.ts`: `applyLocale(session, { locale, currency, country })` writes all three or throws; resets `cartId` when currency changes (no UI in v1).
- `<html lang>` from the active locale in `app/[locale]/layout.tsx`. This layout **must not read the session** (D20).
