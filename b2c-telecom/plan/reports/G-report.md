## Missed features and deviations
- **Required set attributes dropped.** The platform rejects `isRequired: true` on set attributes (`isRequired=true is not supported for attribute type 'set'`): `anchors`, `audience`, `applies-to-families`, `supported-technologies`, `compatible-plan-families` are optional now (the seed data always fills them; `validateCatalog` rejects a required set so it cannot come back).
- **Price keys use `_` not `.`**: `<sku-lower>_<currency-lower>_<policy key | once>` (e.g. `mlv-cbl-500-24m_usd_malva-monthly`); the platform allows only alphanumerics, `_` and `-` in keys.
- `malva-equipment.charge-type` has constraint `None`, not `Unique` (one name = one definition; the shared definition wins).
- Empty set attributes (`channels`, `included-offers`, `compatible-addons`, `conflicts-with`) are **omitted** instead of stored as `[]`; unset means empty.
- All shared attributes carry the same `isSearchable` (the docs say the attribute is not searchable if it differs between types), so `contract-term`, `charge-type`, `technology`, `data-gb`, `downstream-mbps`, `network-generation`, `badge`, `addon-kind`, `addon-tag` are searchable on the descriptive types too. `isRequired` still differs per type.

## Findings
All values observed live on 2026-10-07 against `spec-test-b2c-telecom`.

### 1. Inventory mode (D-019), run by `npm run seed:experiments`
Service line `MLV-ADD-SPOTIFY-MTH` (no InventoryEntry), US/USD cart, with a customer and shipping address:
| Mode | Cart | Order from the cart |
| --- | --- | --- |
| `None` | accepted | **accepted** |
| `TrackOnly` | accepted | refused: `400 OutOfStock: Some line items are out of stock at the time of placing the order: MLV-ADD-SPOTIFY-MTH` |
| `ReserveOnOrder` | accepted | refused: same `OutOfStock` |
Handset `MLV-DEV-NOVAPRO-VLT-512` (stock 0): `None` order accepted, `TrackOnly` order accepted, `ReserveOnOrder` order refused (`OutOfStock`). Stocked handset (200) with `ReserveOnOrder`: cart and order accepted. **Rule held: cart/order mode stays `None` (D-019 default)**. Consequence: `None` never blocks an order for lack of stock, so the out-of-stock handset is enforced by the app reading the inventory entry (M `lib/ct/availability.ts`), not by the platform. A mixed cart (services + handset) cannot use a stock-enforcing mode.

### 2. Predicates (backtick escape) and discounts
``attributes.`offer-family` = "phone"`` and the other backtick-escaped attribute names are **accepted** in cart discount `cartPredicate`, `target.predicate` and pattern-target predicates, and in the two shipping method predicates (F's methods now exist). Smoke tests (US/USD, prices in cents):
- second line: 2 x Unlimited (2 x 5000) total 9000; 5 x Unlimited total 21000 (lines 2 to 5 get $10 off each, the first pays full).
- bundle: Unlimited + Cable 500 12M: the cable line 6499 → 5999, phone line unchanged; Unlimited alone: no discount.
- first month free: Air 5G 12M (5500) total 0 (`intro-free-months > 0`).
- tier: Cable Gig 24M 7999 → 6399 (20 %).
- `WELCOME10` on a 5000 cart: cart total 4000, code state `MatchesCart`.
- `GET shipping-methods/matching-cart`: add-on-only cart → `standard-shipping, express-shipping, malva-delivery-digital`; mixed (plan + add-on) and device-only carts → `standard-shipping, express-shipping, malva-shipping-standard`. The sample methods `standard-shipping`/`express-shipping` match every cart (they have no predicate): BFF must filter by the `malva-` prefix (F's TODO).
Fallback for the backtick escape is not needed.

### 3. Custom field String size
`malva-order.labelSnapshot`: 4096 characters accepted at order creation, 8192 and 65,536 characters accepted with `setCustomField`. No limit reached at 64 KB.

### 4. `malva-cart` → `malva-order` handover
`resourceTypeIds: ['order']` does cover carts (a cart can be typed `malva-cart`). An order created from a `malva-cart` cart keeps the cart's custom type and all its field values. `OrderFromCartDraft.custom` with `malva-order` on such a cart is refused (`Source customFields have typeId … that doesn't correspond to the one in CustomFieldsDraft … Merged custom fields need to have the same type.`). Working options: (a) `setCustomType` on the cart to `malva-order` (with the fields) before ordering, then the order keeps `malva-order`; (b) `setCustomType` on the order after creation (fields not repeated are dropped). Simplest: type the cart `malva-order` from the start. G-19's demo orders do this.

### 5. Recurring orders
Creating an order from a cart with recurring lines **automatically created an Active Recurring Order** within seconds (`startsAt` = order creation time). Requires a customer on the cart. Demo orders `MLV-DEMO-0001..3` each have one. Experiments cancel (`setRecurringOrderState` canceled) and delete theirs; deleting works only after cancel.

Image attachment (35 updates) did not need a visible wait. Query limit: at most 50 expressions per search request (F's wait now chunks).
