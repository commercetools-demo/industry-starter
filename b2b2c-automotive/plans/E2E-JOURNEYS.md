# End-to-end journeys on the live project (workstream Z-05)

Run these once on RELEASE builds (`npm run build && npm run start` in both apps) against the seeded project `spec-test-b2b2c-automotive` after the owner rows OA-01, OA-02, OA-05 and the seed are done. Claude runs them through the Chrome DevTools MCP and reads the result back through the `b2b2c-automotive` MCP; the owner is needed only for the credential rows and the real-device rows. Record step, URL, observation and screenshot in `plans/evidence/Z/journeys.md` (screenshots `plans/evidence/Z/browser/`).

Conventions: storefront `http://localhost:3000`, portal `http://localhost:3001`. Store A is `mau-reseller-north` (Kuestenwerk), store B is `mau-reseller-south` (Suedkamm). Every record a journey creates carries the prefix `TST-` (order PO or note, subscription note, review title, return note) and is added to a register `plans/evidence/<letter>/test-data.md` as a table row `| kind | id | note |` so `seed` `npm run purge:test-data` can remove it (M-Z-03). Never put the demo password in a note, URL, log or screenshot; it lives in `seed/.env.local` and the apps' `.env.local` (`DEMO_LOGIN_PASSWORD`).

## After the journeys

1. Run `cd seed && npm run purge:test-data` (dry run) and save the output to `plans/evidence/Z/purge-plan.txt`; the owner reads it (M-Z-03) before `--apply --confirm <projectKey>`.
2. `read_orders`, `read_carts` (state `Active`), `read_recurring_orders`, `read_reviews` for anything created after the first test: only intentionally kept journey orders may remain, listed in `plans/evidence/Z/leftovers.md`.
3. Anything that failed goes to `plans/evidence/Z/fixes.md` with the journey number; fix, rerun that journey.
