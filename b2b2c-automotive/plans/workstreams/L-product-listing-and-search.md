# Workstream L: Product listing and search

**Depends on:** E (parts, prices, stock, ratings data), F (stores, selections, channels), I (shell, branch in session), J (fitment helpers, `getActiveVehicle`, `FitBadge`, `FitToggle`, `GarageBar`).
**Implements:** `cs/design-product-listing-page` (primary).
**Skills:** `commercetools-platform` (`product-search.md`), `commercetools-storefront` (`b2c/product-listing.md`, `core/search-facets.md`, `core/cart.md`, `core/data-loading.md`, `core/performance.md`), `commercetools-commerce-patterns` (price selection, catalog architecture).
**Apps and paths:** everything below lives in `b2b2c-automotive/storefront/`. Run commands from that directory.

## 1. Goal

One server-rendered listing serves "All parts", a category and search results. It shows only products of the reseller's store, the reseller's price, the selected branch's stock, the fit state for the active vehicle, and holds filters, sort and page in the URL. Add to cart works from a card (this workstream creates the add-to-cart endpoint and hook; M and N reuse them).

## 3. Design decisions already taken

| # | Decision | Source |
| --- | --- | --- |
| D1 | Use the Product Search API (`apiRoot.products().search().post`), never `productProjections().search()`. | `commercetools-storefront` MEDIUM tier; `product-search.md` pattern 1 |
| D2 | Search returns ids, facets and total only. Cards are built from a second call, the in-store ProductProjection query (name, images, tailoring, availability), plus a **batched Standalone Prices read** for the amounts (D4). Reason: Product Search cannot return price data (docs "Product Search › Prices": standalone prices are indexed for sort, filter and facets but are not retrievable), search `productProjectionParameters` is deprecated since December 2025, and in-store projections apply Product Tailoring (search does not). | commercetools docs "Product Search" (no tailored data, no price retrieval; `productProjectionParameters` deprecation) |
| D3 | Assortment scope is the `stores` field: `exact stores = <storeId>`. A product withdrawn from the store's selections is absent. | `design-product-listing-page` L-R1; docs "Filter by Store and Product Selection" |
| D4 | **Price model: all prices are standalone prices** (owner answer Q-003; answers Q-L03). Products have `priceMode: Standalone`; each SKU has, as seeded (`seed/src/data/prices.ts`), a **Malva base price** without channel per currency and country (`<sku>__base-eur-de`, `<sku>__base-usd-us`), an optional **reseller retail price** on the store retail channel (`<sku>__mau-dist-north`, `<sku>__mau-dist-south`, USD `...__usd`; about half of the carried parts) and an optional **branch price** with `channel` = the branch channel (`<sku>__mau-br-<store>-<city>`; about one in seven items; Q-005). Reseller-owned items (local parts, own bundles) have only a retail-channel price and no base price. **Selection order: branch channel, store retail channel, Malva base.** The price for a card is chosen by one pure function `selectStandalonePrice(prices, { currency, country, channelIds: [branchChannelId, retailChannelId] })` (same function as I's `selectPrice`, I D6, one implementation): a price on the branch channel beats the retail channel price, which beats the channel-less base price; every seeded price has a country (EUR/DE, USD/US), so a price whose country equals beats one without country; no customer group is used (no customer-group pricing in this phase); a price with a valid time range beats one without. Amounts come from `GET standalone-prices?where=sku in (...) and currency="X"`, one call for the listing, never one per card (`lib/ct/prices.ts`). Product Search price **sort and filter** use the indexed `variants.prices` with the same scope (currency, country, channel, falling back to prices without channel, see L-03). **There is no `priceCurrency/priceCountry/priceChannel` on projections and no embedded `masterVariant.price` anywhere in the storefront.** L-00 records which read path returns the discounted price (`StandalonePrice.discounted` from a Product Discount) in `plans/evidence/L/mcp-checks.md`. | owner-answers Q-003, Q-005; docs "Product Search › Prices"; `design-product-listing-page` Platform notes |
| D5 | Fit-only by default when a vehicle is active; `fit=0` turns it off; the URL never carries the vehicle. Fit is evaluated on **year ranges** (J): the query uses the active vehicle's expanded range keys (`fitScope(keys, mode)`), the card uses `getFitState` over the product's `fitment-keys`. | design.md decision 5; J D1, D7, D8; owner-answers Q-J03 |
| D6 | **Exact part or OE number search bypasses the fit-only filter** (owner answer Q-L02, matches the plan), is ranked first on page 1 and shows its fit badge. | owner-answers Q-L02; `design-product-listing-page` "Part number search" |
| D7 | Facets are application configuration (`lib/search/facet-config.ts`), not Contentools. | `design-product-listing-page` Platform notes; design.md section 2 |
| D8 | Numbered pagination, 24 per page, links with `rel="prev"` and `rel="next"`; search and filtered pages are `noindex`. | `design-product-listing-page` Layout ("pagination or load-more is required"); this plan |
| D9 | Routes: `/[locale]/[store]/parts` (all parts), `/category/[slug]`, `/search?q=`. One shared `ListingPage` server component. | `bootstrap-and-structure` directory structure |
| D10 | **"Most popular" is a seeded flag/rank** (owner answer Q-L01): number attribute `popularity-rank` (1 is the most popular, absent means unranked), sorted ascending with unranked last; there is no sales analytics. **The seed has neither `popularity-rank` nor reviews yet**: both are seed requests (section "Seed requests", `plans/notes/seed-requests.md`); until they exist the popular sort falls back to name order and the rating row and "Top rated" stay hidden. **"Top rated" uses review rating statistics** (`reviewRatingStatistics` on the product, from reviews); the rating row is hidden when a product has no reviews. | owner-answers Q-L01 |
| D11 | A card adds the master variant when the product has one variant; otherwise its button reads "Choose options" and links to the product page. | this plan |
| D12 | Never show a zero price; no standalone price for the shopper's currency, country and branch (after fallback to the base price) means "Price unavailable" and a disabled Add to cart. | `design-product-listing-page` L-R5 |

## 4. Data contract (verified in L-00; written by E and F)

Names are the seed's (`seed/src/data/product-types.ts`, kebab-case). Product type `mau-pt-part` attributes (flat, `isSearchable: true` unless noted): `brand` enum (7 fictional brands, for example Vektra, Kestrel); `quality-tier` enum (`oem`, `oes`, `premium`, `economy`); `part-number` text; `oem-numbers` set of text; `position` enum (the only part-specific facet in the seed; others appear when the seed adds them); `fitment-keys` set of text (range keys `make|model|year-from|year-to|engine`, J) and `universal-fit` boolean; `warranty-months` number; `size-spec` text (not searchable); `recurring-eligible` boolean (M, N, Q: subscribable); core-charge money attributes (not searchable). **Not in the seed (seed requests): `popularity-rank` number and reviews** (Q-L01); build against the contract and ask the coordinator through `plans/QUESTIONS.md` if absent at L-00. Local reseller parts (`mau-pt-local-part`) carry `part-number`, `brand-name`, `owner-store`, `review-state` and no fitment; bundles (`mau-pt-bundle`) carry `component-skus`, `component-quantities`, `bundle-discount-percent`, `owner-store`. Prices: **standalone prices** (D4): per SKU a channel-less Malva base price (EUR/DE and USD/US), optional prices on the store retail channel and optional prices with `channel` = a branch, currency EUR (de-DE) and USD (en-US); the pre-release part `MLV-BP-41099` has no price at all ("Price pending"). Inventory entries per sku per branch supply channel (plus the Malva warehouse `mau-supply-malva-dc` for "ships later"; about 70 % of carried items are in stock at a branch).

## Notes (workstream L, 2026-10-12)

Where the build differs from the plan, and why. Evidence in `plans/evidence/L/`.

- **Syntax confirmed with the docs MCP** (details in `plans/evidence/L/mcp-checks.md`): `categoriesSubTree` exact filter, `reviewRatingStatistics.averageRating` sort, sort `filter` with a compound expression, `exact` `values`, `isOnStockForChannel`, facets scoped to the query by default. **`missing: 'last'` does not exist** (the SDK type has no such key; products without a sort value come last), so the popular sort has none. **`not` takes an array**: `{ not: [ { exists } ] }`. `categoriesSubTree` as a facet, `not`/`exists` and `values` on `variants.prices.channel` inside a sort filter, and `storeProjection` are live rows.
- **Seed now has `popularity-rank` (14 ranked parts) and 22 reviews on 9 parts**: D10 applies as written; the popular and rating fallbacks stay in the code path (unranked last, rating row hidden) but are not needed.
- **Store projections**: the SDK has no list call under `in-store/key=`, so `getListingProjections` uses `GET product-projections?storeProjection=<storeKey>&where=id in (...)&localeProjection=<locale>` (assortment and tailoring of the store). Its request carries no price arguments.
- **Paths**: routes are `app/[locale]/[store]/parts|search|category/[slug]` (no `(shop)` group, as the coordinator specified). `ProductCard`, `ProductGrid` are in `components/listing/` (not `components/product/`). Page assembly is `lib/listing/load.ts` (server-only, mocked in `ListingPage.test.tsx`); `ListingPage` only renders. `mapProductSummary` has no `store` argument (nothing in it needs the store; the page passes `shipDays` and the city to the card). Price selection is pure in `lib/store/standalone-price.ts` (re-exported from `lib/ct/prices.ts`) so mappers do not import the SDK client; it wraps `selectPrice` of `branch-scope.ts` (one channel order implementation).
- **Params**: `ListingParams` has `sortGiven` (a search without an explicit `sort` is ordered by relevance and its select offers "Best match" first; a listing keeps the four options). `page` is capped at 400 (Product Search `offset + limit` limit 10000).
- **Part number search**: the exact request ignores the fit scope but honours brand, part and pickup filters; on page 1 its ids come first. The total counts an exact match once when the fit scope is on and the main result fits one page; with more than 24 text matches an exact match beyond page 1 may be listed twice across pages (rare, accepted).
- **Add to cart**: `addLineToCart` also checks the sku against the store's assortment (404 when withdrawn) before the price (422) and reads inventory for the branch supply channel. `anonymousId` was added to the session (`Session`, `SESSION_KEYS`); it is minted on the first cart and N's `ensureAnonymousId` can build on it. `recurrencePolicyKey` is validated and passed to `addLineToCart` but not applied (N-03).
- **Images**: cards use `next/image` with a render-time loader (`components/listing/image-loader.ts`, Image source sized with `?auto=compress&cs=tinysrgb&w=`), so no optimizer host config; the browser loads from the image host, therefore `CSP_IMG_HOSTS` must list it (`.env.example` says which). A card without a photo keeps the 4:3 slot with "No photo" (OA-03).
- **Layout**: page padding and gap are 16 px below 1024 px (24 px above); with the 24 px values only one 451 px column fitted beside the 230 px panel at 768.
- **Messages** are two-level namespaces `listing`, `filters`, `card`, `pagination` (Q-J07). Quality and position labels come from the catalogues (the seed's enum labels are English only); brand labels come from the product type through `lib/ct/attribute-labels.ts` (TTL cache one hour, like G).
- **Scopes added**: `view_products`, `view_standalone_prices` (`lib/scopes.ts`, `.env.example`); the frontend API client needs both (OA-01).
