# Workstream I: Storefront shell and store picker

**Depends on:** B (tokens), C (locale routing), F (stores, channels seeded), G (BFF core, session), H (theme adapter, Contentools wiring).
**Implements:** `cs/design-storefront-shell` (primary), `cs/design-store-picker` (primary).
**Skills:** `commercetools-storefront` (`b2c/navigation.md`, `b2c/optional/bopis.md`, `core/data-loading.md`, `core/performance.md`), `commercetools-platform`, `commercetools-commerce-patterns` (channels and inventory modelling).
**Apps and paths:** everything below lives in `b2b2c-automotive/storefront/`. Run commands from that directory.

## 1. Goal

Every shopper page is wrapped by one shell: utility bar, header (wordmark or logo, store chip, search, sign in or account, cart count), first-level category navigation, footer. A modal store picker (list and map) lets the shopper choose a branch of the reseller that owns the store path. Choosing a branch changes stock, pickup promise and the price (a branch is a channel that carries both inventory and prices; owner answers Q-005 and Q-I04) and, if you re-read the page, everything derived from them. After this workstream a junior on J, K, L, M can build pages that simply sit inside `app/[locale]/[store]/layout.tsx`.

## 3. Design decisions already taken

| # | Decision | Source |
| --- | --- | --- |
| D1 | Header and footer are application components styled only by tokens. Store name, logo, favicon come from store settings, not Contentools. | `theming-design` "Header and footer are application components"; design.md section 2 |
| D2 | The picker lists branches of the reseller that owns the store path, never other resellers. | design.md decision 6 |
| D3 | Currency, country, tax label, free-shipping threshold come from store configuration and `COUNTRY_CONFIG`, never the prototype's "Canada (CAD $)" or "$99". | design.md decision 7 |
| D4 | No raw hex, px font sizes or font names in components; tokens only (`check-tokens`). | design.md decision 9 |
| D5 | **One store per reseller; branches are channels on that store that carry both inventory and prices** (owner answer Q-005, answers Q-I01). Each branch channel has roles `InventorySupply` and `ProductDistribution`; the store lists it in `supplyChannels` and `distributionChannels`. | owner-answers Q-005; design.md open question E; `design-store-picker` Platform notes |
| D6 | **A branch can change the price as well as stock and pickup** (owner answer Q-I04, follows from Q-005). All prices are standalone prices (Q-003), as seeded (`seed/src/data/prices.ts`): a Malva base price without channel per currency and country (`<sku>__base-eur-de`, `<sku>__base-usd-us`), an optional reseller retail price on the store retail channel (`mau-dist-north`, `mau-dist-south`; key `<sku>__<channelKey>`, USD `<sku>__<channelKey>__usd`), and an optional branch price with `channel` = the branch (key `<sku>__<branchKey>`). **Price selection order: branch channel, store retail channel, Malva base.** The store's distribution channels are the retail channel plus its branches, so the store lists both kinds. The session carries `branchKey`; `getBranchScope` (I-04) returns the branch channel (supply channel and first price channel), the store retail channel (second price channel) and the pure `selectPrice` order. | owner-answers Q-005, Q-I04, Q-003; `design-store-picker` Purpose; seed `prices.ts` |
| D7 | **Map is Leaflet with OpenStreetMap tiles; no API key** (owner answer Q-I02). Tile attribution "© OpenStreetMap contributors" stays visible; the CSP allows the tile host only. "Postal code or city" is geocoded with **Nominatim** through a server-side proxy route with a cache, a debounce and the usage-policy limits (D13). The list stays the primary control, the map an enhancement, and the picker still works when geocoding or tiles fail. | owner-answers Q-I02; `design-store-picker` "Gaps and decisions", "Keyboard and screen reader use" |
| D8 | Picker opens automatically only when no branch is chosen and more than one exists; dismissing keeps the default branch and does not reopen in the same tab (`sessionStorage`). | `design-store-picker` "Layout" recommendation |
| D9 | No mobile hamburger menu and no mini-cart drawer in this phase: nav scrolls sideways, cart button links to the cart page. Both are listed as design gaps (design.md section 6, SO-01). | `design-storefront-shell` "Responsive behaviour", "Gaps" |
| D10 | Native `<dialog>` with `showModal()` provides focus trap and Escape. | `design-store-picker` "Keyboard and screen reader use" |
| D11 | Chosen branch is stored in the session as `branchKey` (added to `lib/session-core.ts`; reset together with `cartId` when the store changes). | `bootstrap-and-structure` "Stateless session" (extension) |
| D12 | Category navigation shows a root category only when at least one product of the store is in its subtree (one Product Search facet call, cached 5 minutes per store and locale). | `design-storefront-shell` "Category navigation and active state" |
| D13 | Nominatim usage rules (public instance, policy at operations.osmfoundation.org/policies/nominatim): at most 1 request per second per server instance (serialised queue), a valid identifying `User-Agent` and `Referer`-less server calls with a contact address from `NOMINATIM_CONTACT` (env, required when geocoding is enabled), results cached 24 hours by normalised query, no autocomplete (search runs after a 600 ms debounce and a minimum of 3 characters, or on Enter), `countrycodes` limited to the store's countries, `limit=5`. The browser never calls Nominatim; it calls `GET /api/store-context/geocode?q=`. `GEOCODER_URL` defaults to the public instance and can point to a self-hosted one; `GEOCODER=off` disables it (the list then filters by text as before). | owner-answers Q-I02; Nominatim usage policy |

## 4. Data contract (written by D, E, F; verified here, never hand-created)

| Object | Shape |
| --- | --- |
| Custom type `store-settings` on resource `store` (seed-owned, `seed/src/data/custom-types.ts`; this workstream never creates or alters it) | fields read here: `logoUrl`, `faviconUrl`, `freeShippingThresholdCent` Number, `shipDaysMin`, `shipDaysMax` Number, `timezone` String (IANA, e.g. `Europe/Berlin`), `helpUrl`, `trackUrl`, `currency`, `taxLabel`, `defaultCountry`; location fields `addressLine`, `postalCode`, `city`, `countryCode`, `latitude`, `longitude` (store-level fallback only; branches carry their own address). Other fields (`ownerBusinessUnitKey`, `returnWindowDays`) belong to other workstreams |
| Custom type `branch-info` on resource `channel` (seed-owned) | fields `openingHours` String (JSON `{"mon":["08:00","19:00"],"tue":[...]}`; a missing day means closed), `pickupMode` Enum `same-day` \| `next-day` \| `ship-to-store`, `phone` String, `timezone` String (IANA of the hours, e.g. `America/Chicago` for the Austin branch), `storeKey` String |
| Store | `distributionChannels` = the store retail channel (`mau-dist-north` / `mau-dist-south`, role `ProductDistribution`) plus its branches; `supplyChannels` = the warehouse `mau-supply-malva-dc` plus its branches. Branch channels (keys `mau-br-<store>-<city>`, roles `InventorySupply` and `ProductDistribution`, native `address` with `postalCode`, `city`, `streetName`, and `geoLocation`) are the picker rows: pick branches as the channels with custom type `branch-info`, never the retail channel or the warehouse. Both seeded stores have 3 branches (north: Hamburg, Berlin, Bremen; south: Munich, Stuttgart, Austin). Prices: standalone prices; Malva base without channel (per currency and country), optional retail price on the store retail channel, optional branch price with `channel` = the branch; selection order branch, retail channel, base |
| Categories | root categories with localized `name` and `slug` in `de-DE` and `en-US` |

Task I-00 checks these with the MCP. If anything is missing, stop, write the gap in the PR description and report it to the coordinator; do not create project data yourself.
