# Route inventory and policy (workstream X-00, X-01)

Generated from `portal/lib/authz/route-policy.ts` and `storefront/lib/authz/route-policy.ts` (the source of truth, one `p('<route>', { METHOD: access })` line per Route Handler under `app/api/**`). `node scripts/list-routes.mjs` lists the route files; `scripts/check-route-policy.mjs` (run by `npm run check` through `check-routes.mjs --static`) fails when a route file has no policy line, a line has no route file, or an exported method has no access. `lib/authz/route-policy.test.ts` runs every line against the real handler with synthetic personas and traps every commercetools client and `fetch`: a refusal is only counted when the status is exact and the trap count is zero.

Access vocabulary. Portal: `public`, `session` (any signed-in user), or a `PortalAction` of `lib/authz/permissions.ts` (store in session and role checked by `authorizeStore` before any commercetools call; Admin-only unless the action lists Buyer). Storefront: `public`, `cart` (the visitor's own session cart), `customer` (signed-in shopper, queries scoped by customer id and store key), `token` (signed single-use token or private link), `dev`.

Every state-changing method of every route additionally passes the same-origin gate in `proxy.ts` (`lib/security/api-gate.ts`, decision D5), proven by `proxy.api-gate.test.ts` and `csrf-curl.txt`. Deviation from the plan: the plan asked every mutating route to be wrapped in `withRoute`. One gate in the proxy covers all routes with no per-route edit, cannot be forgotten by a new route, and runs before any handler; the route policy gate stops a route without a policy line. No route was renamed relative to the plan except where the plan used intended names (`PUT /api/seller/prices`, `POST /api/seller/prices/bulk` match; the storefront checkout is `POST /api/checkout/session` with no body and `GET /checkout/return`).
