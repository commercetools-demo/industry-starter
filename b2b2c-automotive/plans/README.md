# plans/

Implementation plan for the Malva B2B2C automotive project: a reseller storefront for drivers and workshops (`storefront/`) and the Malva Partner Portal for resellers (`portal/`), written for junior developers to follow task by task.

| File | Purpose |
| --- | --- |
| `JUNIOR-GUIDE.md` | **Start here.** Rules, the task loop, tests, how to verify on your own, how to report manual testing, when to stop and ask |
| `DEPENDENCY-PLAN.md` | Workstreams A to Z, who depends on whom, waves, gates |
| `workstreams/<LETTER>-*.md` | One file per workstream: design, tasks, scenario checklist, browser recipe, definition of done |
| `STATUS.md` | Progress (counts generated by `verify-plan.mjs --sync`) and environment status |
| `DECISIONS.md` | Decisions already made (owner decisions and verified platform facts) |
| `QUESTIONS.md` | Open questions to the owner, the default taken for each, and the ones juniors add |
| `TODO-MANUAL-TESTING.md` | **Everything only the owner can do or test**: actions (OA), sign-offs (SO), manual tests (M) |
| `SPEC-COVERAGE.md` | Which workstream implements which spec (generated) |
| `PROJECT-FINDINGS.md` | Verified platform facts and environment findings |
| `IDEAS.md` | Parked ideas |
| `verify-plan.mjs` | `node plans/verify-plan.mjs [--sync] [--strict]`: checks the plan is consistent with the specs and regenerates the generated blocks |
| `evidence/<LETTER>/` | Screenshots, MCP read-backs and logs a workstream produced while verifying itself (no secrets) |
| `notes/questions-*.md` | Per-workstream question drafts; the lead consolidates them into `QUESTIONS.md` |

Specs: `../openspec/specs/{consumer-storefront,seller-portal}/` (only `bootstrap-and-structure`, `theming-design` and `design-*`; the other directories are generated templates and are ignored). Design decisions and open questions: `../openspec/changes/b2b2c-automotive-design/design.md`. Design export: `../design/`.
