## Design
Cart = commercetools **Cart**, `currency USD`, `country US`, `shippingMode Single`, tax mode Platform, line items = medications only (D1: bookings are never in the cart). Each line item carries custom type `mlv-rx-line` fields (`rxNumber`, `rxLineRef`, `prescribedQty`); **quantity = prescribed quantity and is not editable** (no quantity control; "Qty N" text). Adding the same RX line twice replaces the existing line (idempotent by `rxNumber+rxLineRef`, not an error). Added through `POST /api/cart/rx-lines { rx, lineRefs[] }`: server re-validates with N (`validateRxSelection`), creates the cart on first add (`customerId`, `anonymousId` none — signed-in only, so carts are customer carts) and sets `cartId` in the session, adds lines with `addLineItem` (by SKU, `quantity`, custom fields), returns the cart. A cart GET (`/api/cart`) **re-validates every line** on load: lines whose authorization expired/exhausted, ceiling now lower, or out of stock are returned with `unavailableReason`. The BFF never silently removes lines: it flags them, the patient removes them with Remove, and until then Checkout is disabled with "Fix N items to continue". The summary shows the platform total; the design's "total excludes it" is met by showing flagged lines as struck-through and the **payable total** from a platform recalculation of the cart **without** them is not possible without mutating the cart, so the summary adds the line "N unavailable item(s) not included" and Checkout stays disabled (accepted simplification). Price change since add: platform reprices on read (`recalculate` with `updateProductData: true`); lines whose unit price changed since the previous read show a "Price updated" note (compare to `custom.lastSeenUnitPrice` on the line, updated on each read).
Cart page `/cart` (sign-in required, "Sign in to view your cart."): page head "Your cart"; two columns (lines; 380 px summary); line rows name, "<RX number> · Qty N", price, **Remove** as a real button (announces "Removed <name>" via the live region); summary: Subtotal, "Standard delivery" with green FREE badge or the calculated fee, Total (navy 20 px bold) from `cart.totalPrice`/`taxedPrice` — **no number the platform did not calculate**; full-width Checkout button → `/checkout`; empty state "Your cart is empty." + "Find a prescription". Cart count in header = number of lines (Q-020). Discount codes: not in the design → the "Discount code rejected" scenario of cart-management is satisfied only if a code field exists; **no code field in v1** (cart-management scenarios mapped as N/A with that reason). Minimum order value: none (cart-page "Below minimum order value" is N/A: no minimum configured).
Concurrency: 409 → refetch + retry once (G-08).
