## Design
Server-only tier, built exactly as `bootstrap-storefront/specs/storefront-bff-and-session`.
- `lib/ct/client.ts`: the single `apiRoot` (`ClientBuilder` client-credentials, `withProjectKey`). Env validated lazily on first use **and** at server start (`instrumentation.ts`): a missing `CTP_PROJECT_KEY`, `CTP_AUTH_URL`, `CTP_API_URL`, `CTP_CLIENT_ID`, `CTP_CLIENT_SECRET`, `CTP_SCOPES` throws an error naming the variable, not a commercetools auth error.
- `lib/session.ts`: jose HS256 token in an HTTP-only, `SameSite=Lax`, `Secure` (not in local dev), `path=/`, 30-day cookie named `malva_session`. Payload only `customerId`, `cartId`, `country`, `currency`, `locale`. `SESSION_SECRET` missing or < 32 chars throws at import except when `NODE_ENV==='test'`. Tampered/expired cookie → empty anonymous session, no error to the visitor. Helpers: `getSession()`, `updateSession(patch)`, `clearCustomer()` (sign-out: drop `customerId`+`cartId`, keep locale), `clearCart()` (after order).
- Route Handler shape: validate session → call **one** function in `lib/ct/<namespace>.ts` → return JSON; patient-data endpoints answer 401 `{ error }` without a `customerId` and call no commercetools function; commercetools errors are mapped to a safe `{ error }` (never the raw SDK error, request body or credentials) by `lib/api.ts` `handle(fn)`.
- Type boundary: `lib/types.ts` (app types), `lib/mappers/` (SDK → app). Skeleton only; real types arrive with their workstreams.
- `GET /api/health` (dev only) → `{ ok: true, projectKey }`, else `{ ok:false }` 500; returns 404 in production and a check fails if the file exists on a release build.
- Cookie holds ids only: **no** name/email/DOB/Rx/booking (health-data-minimization).
Frontend client scopes: B2C template + `manage_sessions`, `manage_orders`; extra scopes (e.g. Custom Objects, which the clinical/scheduling modules need, and reviews) are listed with a reason in `.env.example`. **Ask the owner (Q-D-n) before widening scopes**; the likely need is `manage_customers`, `manage_orders`, `manage_my_orders`, `view_products`, `view_published_products`, `manage_shopping_lists`, `view_categories`, `view_shipping_methods`, `view_tax_categories`, `view_states`, `manage_key_value_documents` (custom objects), `view_project_settings`, `view_inventory_entries`, `manage_payments`, `manage_sessions`.
