# Workstream R — Account area: shell, overview, labs, appointments

**Depends on:** F, G, H, J, L
**Implements:** design-account-area, account-dashboard
**Skills:** commercetools-storefront, commercetools-platform

## Design
Layout `app/[locale]/account/layout.tsx`: 240 px side nav (Overview, Lab tests, Appointments, Orders — plus, from later workstreams, Addresses (P), My medicines & Auto-refill & Payment methods (T), Allowance (U): items appear only when their route exists via a `lib/account-nav.ts` registry), "Sign out" outline button (clears session + SWR keys → `/login`); stacks < 900 px. Whole area is **non-cacheable** (`Cache-Control: no-store`, `dynamic = 'force-dynamic'`); lab values never in URLs, analytics or error reports (I-03 redactor).
- **Overview** `/account`: "Hello, <first name>", email, three tiles (Lab results ready, Appointments, Orders; each a link; `0` when none) and "Latest lab results" (3 most recent; empty text "No lab results yet." instead of an empty card); each summary resolves independently — one backing service down shows an inline "couldn't load" tile, not a blank page; session no longer valid → sign-in prompt.
- **Labs** `/account/labs` list (name, "<date> · <laboratory>", badge Results ready/Processing, →; row is a link), `/labs` redirects here; `/account/labs/[id]` detail: "← All lab tests", name + badge, rows Collected / Ordered by / Laboratory, note card; result table (Test, Result value+unit, reference-range bar with marker clamped 4–96% and "< N" text when low bound is 0, flag badge Normal/High/Low — flag also as **text**, not colour only; out-of-range track danger-50); processing test shows header + note only; actions "Download PDF" (server-generated PDF, authenticated GET returning `Content-Disposition`, no values in the URL, Q-045) and "Discuss with a doctor" → the ordering doctor's profile (Q-047). Unknown/foreign id → "Not found." (same body, same status for both). Fixed reference ranges per test (Q-046).
- **Appointments** `/account/appointments`: cards (doctor, "<date> at <time> · Video session | <clinic>", reference badge), upcoming first, past separated, empty "No appointments yet. Book one"; **cancel** upcoming bookings (confirm dialog) up to 2 h before (releases the slot, Q-027); no reschedule in v1.
- **Orders** list is built in S (route `/account/orders` registered here as a stub page that S replaces) — R only provides the tile count source `countOrders()`.
- R-07: after sign-in/registration, guest bookings (cookie `malva_bk` refs and bookings whose email matches the **verified** account email) are attached to the patient (`patientRef` set, guest fields removed, `expiresAt` cleared).
