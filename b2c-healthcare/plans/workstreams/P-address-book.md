# Workstream P — Address book

**Depends on:** H, J
**Implements:** address-book, account-and-self-service
**Skills:** commercetools-storefront

## Design
Addresses are the commercetools **Customer** addresses (`addAddress`, `changeAddress`, `removeAddress`, `setDefaultShippingAddress`, `setDefaultBillingAddress`) — one source for the account page and checkout. Exactly one default shipping address (first address becomes default; removing the default promotes the next saved or leaves none). Fields: full name (first/last), street, additional line (optional), city, state (US 2-letter select), ZIP (`^\d{5}(-\d{4})?$`), phone (US, normalised to `+1…`), country fixed `US`. Validation: **format only**, no provider (Q-042); "Validation cannot resolve the address" is satisfied by an inline non-blocking warning only if the format is valid but the state/ZIP prefix mismatch table (small static check) fails — warning, not a block; checkout can proceed after the patient confirms. UI (not designed → SO-03): `/account/addresses` list cards with Default badge, "Make default", Edit, Remove (confirm dialog), "Add address" modal; reused as the checkout address card source. Account self-service here = addresses + name/password change (Q-048: no notification settings, profile photo, or family accounts). Account page itself (shell) lives in R; P exports components `AddressForm`, `AddressList`, and routes `/api/account/addresses`. Page placement under the account shell is wired in R-02 (P ships the page route `app/[locale]/account/addresses/page.tsx` using a temporary plain layout until R).
