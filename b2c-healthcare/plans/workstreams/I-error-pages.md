# Workstream I — Error pages and env guards

**Depends on:** D, H
**Implements:** error-pages
**Skills:** commercetools-storefront

## Design
Three named conditions, each with at least one route back (design not provided → SO-03): **Not found** (`not-found.tsx`, HTTP 404; links Home, Find a doctor, Prescriptions), **Upstream fault** (`error.tsx` + `global-error.tsx`, HTTP 500; "Something went wrong on our side", Try again + Home; no stack, no raw error text, correlation id only), **Expired session is not a refusal** (a 401 from a patient route renders the `RequireSignIn` card with the route preserved, never an "access denied" page). Unknown doctor id → 404 with the specific copy of design-pdp ("Doctor not found. Back to search"). Other-patient resources use the same not-found copy as nonexistent ones ("Order not found.", "Not found."). Errors reported to logs must not contain health data (JUNIOR-GUIDE §1.6): a `lib/log.ts` redactor drops bodies, query strings and fields named `reason|results|value|sig|email|phone`.
