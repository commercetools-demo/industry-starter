# Workstream J — Identity: sign-in, create account, session lifecycle

**Depends on:** D, H
**Implements:** authentication-and-identity, account-sign-in, account-registration-request, email-verification
**Skills:** commercetools-storefront, commercetools-platform

## Design
No email provider (Q-008): registration **auto-verifies** the email (D-029, Q-073): the BFF creates the customer, then immediately confirms the email through the platform's email-token flow server-side (`customers().emailToken().post` → `customers().emailConfirm().post`), so `isEmailVerified` is true on return. The resend/expired/twice scenarios of `email-verification` are implemented in `lib/ct/identity.ts` and unit-tested but have no UI entry point. **No password-reset UI or route** (Q-070/D-032): the spec stays unbuilt; account-sign-in has no "Forgot password" link; signed-in patients may change their password (`POST /api/account/password`, current + new).
Sign-in card per `design-account-area` (centered 440 px, "Sign in to Malva"/"Create your account", reason line, toggle) — the **card UI is built here**, the account area in R. Sign-in: `apiRoot.login().post()` with `anonymousCart` so the anonymous cart merges (spec "Sign in carries the anonymous cart"); the same generic message for unknown email and wrong password; rate limiting of attempts (5/10 min per email+IP bucket kept in the `malva-ratelimit` container). Redirect: `?next=` sanitized (H-09), default `/account`; signed-in visitors opening `/login` go to `/account`. B2C registration: self-registration with full name + email + password; `account-registration-request`'s "request held until seller activates" is **not** applicable (customers are active immediately, documented in README); its "Address already registered" scenario (generic response that does not reveal existence) and "Verification link expired" are implemented against the token functions. Customer gets `custom.patientRef` (opaque `pt_…`) at creation, and a funding scheme is not assigned by default.
Routes: `POST /api/auth/login`, `/register`, `/logout`, `GET /api/auth/me` (minimal user: first name, initials, email), `POST /api/account/password`. Session write via D-03 helpers.
