# Workstream W — Region and language switching (single region in v1)

**Depends on:** C, D, H, O
**Implements:** switching-region-or-language
**Skills:** commercetools-storefront

## Design
v1 sells in one region (`en-US`, D-005), so the switcher is **not shown** while `getValidCountryConfig()` returns one entry; the code path is built and tested for ≥ 2 entries using a test-only `COUNTRY_CONFIG` extension, so adding a region later is configuration. When it is shown: a header control posts to `POST /api/locale` (G-02): all three of locale/currency/country written atomically. Scenarios: **Region switched before a cart exists** (session updated, URL re-prefixed); **Region switched with a cart** (default Q-"carry or empty": currency change → cart cannot be re-priced → cart is **cleared** with an explicit message "Your cart was emptied because prices are in a different currency", prescription lines can be re-added; the old cart is left to expire) — default accepted; **Product not sellable in the new region** (page shows "not available in this region" instead of a broken price; search excludes it). Price-less products (no price for the new currency) are not purchasable.
