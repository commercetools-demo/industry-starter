# Workstream S — Orders: confirmation, tracking, history, post-purchase

**Depends on:** Q, R

**Skills:** commercetools-storefront, commercetools-commerce-patterns

## Design
- **Confirmation/tracking** `/order/[id]` (sign-in required "Sign in to view your order."): single card: green "Order placed" badge, H1 "Your medication is on its way.", rows Order (`MLV-…`), Items, Deliver to, Estimate ("Today by 8 pm" for same-day, else "1–2 business days"), Total, four-step timeline Order received → Pharmacist review → Packed and shipped → Delivered (steps done are green) **driven by the order State** (`mlv-received|pharmacist-review|packed-shipped|delivered`), not static; buttons "My orders", "Search another RX". Order state described truthfully (a cancelled order says cancelled). "Placement outcome unknown" (network failure after submit): the page for a redirect without a confirmed id offers "Check your orders" and never says "placed" until the order is read. Revisited later: the same page, current state. Another patient's id and a nonexistent id → identical "Order not found." (404).
- **History** `/account/orders`: only the signed-in customer's orders (query by `customerId`), newest first; card: order number, item names (medication names only), total, "Track" outline button; empty "No orders yet. Order from a prescription". Detail = the confirmation page. **Reorder**: a "Reorder" action on an order re-runs N validation for each line and adds the dispensable ones (naming the ones that cannot be added: no refills, expired, out of stock) — satisfies "Reorder with an unavailable item".
- **Post-purchase** (single requirement: shipment state visible, partial shipment, return started, refund state visible): shipment state shown from the order State and `shipmentState`; partial shipment shown when the order's `shipmentState` is `Partial` (a QA state in `advance-order`); **cancellation** allowed until `mlv-packed-shipped` (Q-043): `POST /api/orders/[id]/cancel` sets state `mlv-cancelled`, calls `restoreAuthorization` (N-02), restores allowance/restricted amounts (U hooks, no-op until U), marks payment for refund (Stripe sandbox refund is manual, noted "Refund requested" state shown). Returns of dispensed medicines are not accepted (pharmacy rule): the "Return started" and "Refund state visible" scenarios are satisfied for **cancellations** only — the UI shows "Refund requested/Refunded" from the Payment's transactions; mark scenario variants N/A with that reason. No printable receipt (Q-044 default none).
