## Design
The rule: catalog and other non-personal data → Server Components calling `lib/ct/*`; personal, mutable data (cart, account, orders, appointments, labs) → `'use client'` SWR hook → Route Handler → `lib/ct/*`. `unstable_cache` only for public identical-for-everyone data: project settings 300 s; category tree and shipping methods 60 s; **never** prices, carts, accounts, orders, availability, anything receiving `customerId`/`cartId`/session. `generateMetadata` and the page share one React `cache()`d fetch. Root layout pre-fills `SWRConfig fallback` with `KEY_CART` (when `cartId` exists) and a minimal `KEY_ACCOUNT` user; the display name comes from one `getCustomerById` per request on pages that show it (the cookie has ids only). A stale `cartId` (missing/not active) is tolerated: cleared from the session, page renders. Cart mutation 409 → refetch and retry once. Sign-out clears `KEY_CART`, `KEY_ACCOUNT` client-side. Server → Client props are serializable only; `redirect()/notFound()` never inside `try/catch` (or `unstable_rethrow`).
Locale items finished here: `getValidCountryConfig()` filters `COUNTRY_CONFIG` against project settings (cached 300 s); `setLocale({locale})` writes locale+currency+country together from `COUNTRY_CONFIG` and clears `cartId` on currency change; a partial update is rejected/completed.
