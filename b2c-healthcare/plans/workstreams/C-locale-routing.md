# Workstream C — Locale routing and messages

**Depends on:** A

**Skills:** commercetools-storefront (core/add-country)

## Design
v1 supports one region: `en-US` (country US, currency USD, language en). `COUNTRY_CONFIG` in `lib/utils.ts` is the only place those three values appear; routing locales derive from it; `localePrefix: 'always'`. `proxy.ts` (Next 16 name) redirects unprefixed paths using the `your-shop-country-locale` cookie if valid, else `en-US`, and excludes `/api`, `/_next` and any path containing a dot. Navigation helpers (`Link`, `redirect`, `usePathname`, `useRouter`, `getPathname`) come from `@/i18n/routing`. Messages: `messages/en-US.json`; a missing key logs the key in development and falls back to default-locale text in production. The "region not enabled in commercetools" scenario and the atomic-session scenarios are implemented in G (they need the client and session).
`lib/utils.ts` also gets `getLocalizedString(field, locale)` (fallback order: locale → language → `en-US` → first value) and `formatMoney(centAmount, currencyCode, locale)` (uses the currency's `fractionDigits` via `Intl.NumberFormat`, never `/100`).
