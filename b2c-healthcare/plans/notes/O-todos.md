# Workstream O: live steps (need the project, OA-01 and an API client)

No commercetools credentials were available; everything below is unrun. Commands run from `b2c-healthcare/site`. Cart code was verified against a fake carts endpoint (`test/fake-carts.ts`) and in the browser-less recipe with `MALVA_FIXTURES=1` (curl against the dev server).

1. Seed: `npm run seed` so the `mlv-rx-line` type gains `lastSeenUnitPrice` (Money). Without it the `setLineItemCustomField` update for the stored price fails with a 400 on every cart read that sees a new price. Check the seed updates an existing type (adds a field definition) rather than skipping it; if the seed only creates missing types, add the field definition in the Merchant Center or extend the seed (workstream E).
2. Scopes: the storefront client needs `manage_my_orders`-free cart access, i.e. `manage_orders` or the project's cart scope (create/update carts, query carts by `customerId`). Confirm against `.env.example` scopes; the query `customerId=:id and cartState="Active"` with `var.id` must be allowed.
3. Cart creation: `POST /api/cart/rx-lines` as Sam (`RX-77102`, both lines). In the MC (`read_carts`): `customerId` set, no `anonymousId`, `shippingMode Single`, `taxMode Platform`, `shippingAddress.country US`, `shippingInfo.shippingMethodName` "Standard delivery" with price 0. If the platform refuses the draft because `shippingMethod` cannot be set without an address in the zone or because no zone matches `US`, record the exact error in `PROJECT-FINDINGS.md` (fallback: create the cart, then `setShippingAddress` and `setShippingMethod` in a second update).
4. Line custom fields: lines carry `custom.fields.rxNumber`, `rxLineRef`, `prescribedQty` (30) and, after the first page read, `lastSeenUnitPrice`. Quantity is 1 (a pack), see O-questions 2.
5. Replace: add `RX-77102` line 1 again: the cart still has one line for it (new line id). Add it from another browser tab at the same time: a 409 is retried once.
6. Totals: `/en-US/cart` total equals `totalPrice` in the MC, delivery row FREE; a total in a non-zero tax setup (seed uses a 0% US category, D-033) is `totalPrice`, not net.
7. Native limit error: add `MED-amoxicillin-500-mg` through a cart that already holds the limit (or call the API with quantity above `maxCartQuantity`): expect 400 `LineItemQuantityAboveLimit`; the route turns it into 422 with the ceiling (N-todos 6 asks for the exact error body).
8. Re-validation: set inventory of a medication in the cart to 0 (`MED-lisinopril-10-mg`), reload `/en-US/cart`: the row is struck through with "Out of stock", the button reads "Fix 1 item to continue" and is disabled; Remove it and Checkout is a link again. Expire a prescription (edit `malva-rx` `expiresAt`): "This prescription has expired". The platform itself may also remove lines on a cart update when inventory limits are violated (carts-and-orders overview); note whether the read recalculation does so and tell Q.
9. Price change: change the price of `MED-atorvastatin-20-mg` in the MC, reload the cart: new price, "Price updated" badge, total from the platform; reload again: badge gone (O-questions 5).
10. Sign-out/in: after sign-in the header count and the cart come back (login returns the customer's cart; otherwise the newest Active cart is found by `customerId`).
11. Browser (Chrome DevTools MCP was unavailable): the layout of the 380 px summary column (`nav:grid-cols-[1fr_23.75rem]`), 390 px layout (rows wrap, Remove under the name), focus ring on Remove, struck-through rows and the toast. Only HTML and API assertions were run.
12. `getCartValidated` makes up to three calls on a read (recalculate, optional custom-field update, plus N's catalog/stock/ledger reads per prescription). If the cart page feels slow, cache nothing per patient; consider skipping `recalculate` when the cart was modified less than N seconds ago.
