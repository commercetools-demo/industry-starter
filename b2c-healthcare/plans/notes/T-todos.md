## Live checks of the build

1. **Seed:** `npm run seed` creates type `mlv-list-line` (resource `line-item`) and RecurrencePolicies `mlv-monthly` (Months 1) and `mlv-quarterly` (Months 3). `npm run seed:verify` includes both checks. Existing projects: types that already exist are compared, not changed.
2. **API client scopes:** add `manage_recurring_orders`, `view_recurrence_policies`, `manage_payment_methods` (and `manage_shopping_lists`, already listed) to `CTP_SCOPES`. Confirm the Recurring Orders and Carts calls are not refused for lack of a scope (`manage_orders` also covers the recurring Cart).
3. **Shopping Lists:** save RX-77102 lines from `/prescriptions`; MC MCP `read_shopping_lists`: key `mlv-list-my-medicines-<customerId>`, `customer` set, `deleteDaysAfterLastModification` 360, line custom fields `rxNumber`, `rxLineRef`, `savedUnitPrice`. A foreign list id gives the same 404 as an unknown one. "Add all" with both lines: both in the cart; edit `malva-rx` for one line (refillsLeft 0 via MC MCP) -> that line is named "no refills left" and the other stays in the cart.
4. **Price delta:** change the catalog price of a saved medicine and reopen the list: "Up/Down $x since you saved it".
5. **Recurring Order creation (needs OA-04 for the payment part):** enable auto-refill on a delivered order or from `/account/auto-refill`. MC MCP `read_recurring_orders`: `recurringOrderState` Active, `schedule` StandardSchedule Months 1, `startsAt`/`nextOrderAt` one month out, `cart` expanded with `origin RecurringOrder`, line `recurrenceInfo` = policy + `priceSelectionMode Dynamic`.
6. **`setRecurringPaymentConfiguration` (public beta, SDK has no type for it):** the update action is sent as `{ action: 'setRecurringPaymentConfiguration', paymentStrategy: 'Checkout', paymentAllocations: [{ paymentMethod: { typeId: 'payment-method', id }, allocation: { type: 'Relative', percentage: 100 } }] }` on the recurring Cart after the Recurring Order exists (only evaluated on carts with origin `RecurringOrder`). Confirm the exact action field names against the live API (the docs show the nested type, not the action body). If it differs, only `attachPaymentMethod` in `lib/ct/recurring.ts` changes. Also confirm the expanded recurring Cart carries `recurringPaymentConfiguration` (the gate reads the payment method from it).
7. **Recurring Order actions:** `setRecurringOrderState` paused / active / canceled, `setSchedule` by policy key, `setOrderSkipConfiguration` with `{ type: 'Counter', totalToSkip: skipped + 1 }`. Check that one skip skips exactly one run (is `totalToSkip` cumulative?), that `nextOrderAt` disappears while Paused and returns on resume, and that an update during order creation answers 400 `InvalidOperation` (mapped to a retryable "busy").
8. **Scheduled check:** set `AUTO_REFILL_RUN_SECRET` (16+ chars) in the app and in Netlify, `npx netlify functions:invoke auto-refill-run --headers '{"x-refill-secret":"<secret>"}'` with a refill due within 36 h: counts come back and `malva-refill-log` (MC MCP `read_custom_objects`) gains `<recurringOrderId>.<runForDigits>`. With the RX expired (edit `malva-rx`): the refill is Paused and the page shows "Last run: skipped (...), your prescription has expired."; with `refillsLeft` 0: Canceled and "Auto-refill stopped". Without the header and with a wrong secret: 401; without the env: 503. `GET /.netlify/functions/auto-refill-run` from the public internet must not start a run.
9. **Generated orders (reconcile):** after the platform creates an order from a recurring order, the next run of the function gives it `orderNumber` (`MLV-...`), state `mlv-received` (the `transitionState` uses `force: true`: confirm the state machine accepts it), and `malva-rx` loses one refill with `consumedBy` containing the order id; running the function again changes nothing. Confirm the Order query `recurringOrder(id is defined)` is valid and that the order lines carry the copied `rxNumber`/`rxLineRef`/`prescribedQty` custom fields from the recurring Cart.
10. **Dynamic price:** change the catalog price of a refilled medicine; the next generated order uses the new price (the page says so).
11. **Stored payment methods (OA-04):** the `PaymentMethod` the connector creates: where it keeps brand and last four (custom fields or `name`), that `customer` is set from the cart's `customerId`, `paymentMethodStatus` Active, `default`. If the descriptor comes out as "Card" with no digits, adjust `mapDescriptor` in `lib/ct/stored-methods.ts` (the only place a stored method is read) and record the real shape in `PROJECT-FINDINGS.md`.
12. **Default semantics (spec open question, record in PROJECT-FINDINGS.md):** with two cards, call `setDefault true` on the second WITHOUT clearing the first (MC MCP `update_payment_methods`); do both end up default? Our adapter clears explicitly either way, so the result decides only whether the extra write is needed.
13. **Delete:** `DELETE /payment-methods/{id}?version=` works for a customer's method and the Message `PaymentMethodDeleted` is produced; the deleted default is not replaced. After removing a card an auto-refill was charged to (with confirm), the refill is Paused; resuming says "Save a payment method first".
14. **Cancel of a stored-method payment:** Checkout's automated reversals do not work for stored-method payments; confirm that S's `cancelPayment` (voiding an authorization) does, and what the refund path is after capture (manual). The page says refunds to a saved card cannot be reversed automatically.
15. **Stored methods in the widget:** the cart always carries `customerId` (O); confirm the widget shows saved cards first and offers "Save this card" in the Application used for payment-only mode (it may need enabling on the Application or connector).
16. **No card data:** DevTools on `/account/payment-methods` and `/checkout`: no card input outside the Checkout frame; the Network tab shows no card number or token in any `/api/*` answer.
17. **Cart isolation:** with an active auto-refill, `/cart` still shows the shopping cart, never the recurring cart (`origin="Customer"` filter in `fetchActiveCart`).
18. **Home claim:** with `AUTO_REFILL_ENABLED=true` the home page shows "Auto-refills you can pause anytime"; the claim is true now.
