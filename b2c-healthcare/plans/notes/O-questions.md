# Workstream O: questions and the defaults chosen

| # | Question | Default chosen |
| --- | --- | --- |
| 1 | The agent worktree started at an older commit. | Fast-forwarded to `worktree-b2c-healthcare`. Branch: `worktree-agent-a1341198368aaabb9`. |
| 2 | Cart line quantity: the plan says quantity = prescribed quantity, N says one RX line = one pack (`PACKS_PER_LINE` = 1) and the native `maxCartQuantity` counts packs. | The platform line `quantity` is the number of packs (`SelectedLine.packs`, 1 today); the prescribed quantity (21, 30, ...) is the line custom field `prescribedQty` and is what "Qty N" shows. The native per-order limit therefore applies to packs, as in N. |
| 3 | The platform has no "subtotal" field, but the summary needs one. | `mapCart` (server, `lib/mappers/cart.ts`) sums the platform's own line `totalPrice`s in integer cents; the Total is `cart.totalPrice`, the delivery row is `shippingInfo` (discounted price when present). Cart components and the hook never add anything (AST test O-07). Alternative if this is too loose: drop the Subtotal row (Total and delivery are enough). |
| 4 | `lastSeenUnitPrice` is not in the `mlv-rx-line` type. | Added as a Money field to the seed type (`scripts/seed/data/types.ts`, and the field-name list in `scripts/seed/data.test.ts`). A project already seeded needs `npm run seed` again (see O-todos 1). |
| 5 | "Price updated" is shown on a read that sees a changed price, and the new price is stored at once, so the note disappears on the next read (including a focus revalidation). | Accepted as in the plan ("updated on each read"). The first read after adding stores the price silently (no note). If a persistent note is wanted, store the acknowledged price only when the patient dismisses it (not built). |
| 6 | Where does the cart GET write? | `GET /api/cart` (page read) sends `recalculate` with `updateProductData: true` on every call and, when a stored price differs, one `setLineItemCustomField` update, each wrapped in `withCartRetry`. The header read is `GET /api/cart?view=summary`: one read, no write, no re-validation, so every page does not recalculate. Two SWR keys: `KEY_CART` (summary, header) and `KEY_CART_DETAILS` (page). |
| 7 | Cart creation. | `POST /carts` with `customerId` (never `anonymousId`), `currency` and `country` from the session region, `shippingMode Single`, `taxMode Platform`, `shippingAddress {country}` (the platform needs a country to pick a zone and tax rate; checkout/Q replaces it with the real address) and `shippingMethod` by key `mlv-standard`, so the FREE row is platform-calculated. |
| 8 | Which cart does a signed-in customer get when the session has no usable `cartId` (stale, or after sign-out/in)? | The newest Active cart with that `customerId` (`where customerId=:id and cartState="Active"`, `var.id`), else a new one on the next add. A cart in the session that belongs to someone else or is not Active is ignored. A GET with no cart clears a stale `cartId` from the session (Route Handler, so the cookie is writable). |
| 9 | Replace-not-duplicate. | In one update: `removeLineItem` for every existing line with the same `rxNumber` + `rxLineRef`, then `addLineItem`. The line id changes on replace. |
| 10 | Re-validation of lines already in the cart. | Per prescription, `validateRxSelection` (N) for the lines in the cart; refused rows become `unavailable` with the same reason/details as the prescription card; a prescription that can no longer be found makes `UNAVAILABLE`. Quirk: the monthly ceiling check does not know about the cart, so a line that is in the cart is judged as if it were being added now (right for the "is it still dispensable" question). |
| 11 | `POST /api/cart/rx-lines` body. | N's hook sends `{ rxNumber, lineRefs }`, the plan says `{ rx, lineRefs }`: both are accepted. Partial success: accepted lines are added and the refused rows come back in `refused`; nothing addable gives 422 `{ code: 'NOTHING_ADDED', refused }`. A platform `LineItemQuantityAboveLimit` error on the update is mapped (N's `mapLimitError`) to the same 422 shape. Unknown/foreign prescription: 404 "Prescription not found." (no rate limiting here: the number was just validated by the lookup). |
| 12 | Disabled Checkout wording. | The disabled button's label is "Fix N item(s) to continue" (as the plan says), with the note "N unavailable item(s) not included. Remove them to continue." above it; enabled it is a `Checkout` link to `/checkout`. The total is the platform total of the whole cart (flagged lines included, struck through): the plan's accepted simplification. |
| 13 | "Removed <name>" announcement. | `useToast().show({ message })`: the provider's live region announces it and a visible toast shows it for 5 s. No second live region. |
| 14 | Header cart count for signed-out visitors. | `useCart` makes no request unless the account key says signed in (the layout seeds it), returns `null` data when signed out, and reads once on a sign-in transition (a sign-out leaves `null` in the cache, so SWR would not refetch by itself). Sign-out also clears `KEY_CART_DETAILS` (`hooks/sign-out.ts`, its test updated from 3 to 4 keys). |
| 15 | Shared files touched. | `lib/types.ts` (+cart types, `isFullCart`), `lib/api-paths.ts` (+2), `lib/cache-keys.ts` (+`KEY_CART_DETAILS`), `hooks/use-cart.ts` (rewritten; `useAddRxLines()` keeps its signature, N's page tests unchanged), `hooks/sign-out.ts` + `hooks/hooks.test.tsx` (extra key), `messages/en-US.json` (+`cart`), `lib/ct/fixtures.ts` (+`loadCartFixtures`), `scripts/seed/data/types.ts` + `data.test.ts` (+field). No dependency added. |
| 16 | Dev fixtures. | `MALVA_FIXTURES=1` now also gives an in-memory cart per fixture customer (`lib/ct/cart-fixtures.ts`, same production guard). It imitates the platform answer including a sum, only because there is no platform; it is never loaded in production. |
