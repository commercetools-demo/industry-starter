# Workstream X: live steps (need the project and credentials; none were available)

Nothing in `scripts/privacy/` was run against commercetools. All of it is unit-tested against the fake root only. Use the seed admin client (`site/.env.seed.local`); never print its secret.

1. **Erase a throwaway patient (definition of done).** Register a throwaway patient in the browser (`name@example.com`, 10+ character password), book as that patient and as a guest with the same email, add an Rx line, place an order (demo authorize). Then, from `site/`:
   1. `npm run privacy:access -- <customerId> --out ~/privacy-throwaway.json` (the path must be outside the repo). Expect: Customer 1, Cart/Order/Payment >= 1, `malva-booking` 2, `malva-rx`/`malva-lab` 0 (new patient), `malva-dispense-ledger` >= 1, `malva-order-attempt` >= 1, `malva-slot-claim` 2. Check the predicates really work live (item 3 below).
   2. `npm run privacy:erase -- <customerId> --dry-run` and read the id list.
   3. `npm run privacy:erase -- <customerId> --confirm <customerId>`. Attach the ids from the log to the PR (ids only).
   4. Merchant Center MCP: `read_customers`, `read_carts`, `read_orders`, `read_payments`, `read_custom_objects` (containers `malva-booking`, `malva-dispense-ledger`, `malva-order-attempt`, `malva-slot-claim`) show nothing for that customer. `read_project`: `messages.enabled` is false.
2. **Audit after a purchase.** `npm run privacy:audit` after the seed and one purchase: expect "clean". Then paste a sig string into a cart note in the MC and expect exit 1 (then delete the note).
3. **Verify the predicates live** (they were written from the API's field names): `carts` and `orders` by `customerId`; `payments`, `reviews`, `shoppingLists`, `quotes`, `quoteRequests`, `stagedQuotes` by `customer(id=...)`; `businessUnits` by `associates(customer(id=...))`; `messages` by `resource(id in (...))`; `recurringOrders` by `customer(id=...)`; custom objects `value(guest(email in (...)))` and `value(recurringOrderId in (...))`. A 400 from the API names the fix; adjust `QUERIES` in `scripts/privacy/lib.ts` and `collect.ts`.
4. **Recurring orders.** Confirm that a cancelled recurring order for an erased customer is acceptable, or ask commercetools support for erasure of RecurringOrder (the GDPR page does not list it). The cancelled recurring order still holds the customer reference and a recurring cart (the cart is deleted by erase; check the recurring order afterwards).
5. **Retention function.** Netlify site settings: set `RETENTION_SECRET` (16+ random characters, never in git). The storefront API client needs `manage_custom_objects` (and read on the project) for `netlify/functions/retention.ts`. Run once by hand: `curl -X POST -H "x-malva-retention-secret: $RETENTION_SECRET" https://<site>/.netlify/functions/retention` (expect 200 with counts), then with a wrong secret (401). The schedule is `30 3 * * *` UTC in `retention-scheduled.ts`. Run `npm run privacy:retention -- --dry-run` first to see counts.
6. **Messages disabled.** `npm run seed:verify` includes the new check; confirm it passes live (`read_project` -> `messages.enabled: false`).
7. **Network trace of a full journey** (browser recipe): list the requests of search, book, order and confirm that no URL contains a lab value, RX content or reason text.
