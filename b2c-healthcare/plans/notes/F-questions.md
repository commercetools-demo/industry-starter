# Workstream F: questions and the defaults chosen

| # | Question | Default chosen |
| --- | --- | --- |
| 1 | The agent worktree started at an older commit. | Fast-forwarded to `worktree-b2c-healthcare` as instructed. |
| 2 | The plan's slot-claim key is `<doctorKey>\|<mode>\|<ISO start UTC>`. Custom Object keys (and containers) only allow `[-_~.a-zA-Z0-9]`, so `\|` and `:` are not valid. | Key is `<doctorKey>.<mode>.<YYYYMMDDTHHmmssZ>` (e.g. `mlv-doc-amara-okafor.office.20261009T130000Z`), built by `slotClaimKey` in `lib/clinical/slots.ts`. Unverified against the live API (the character rule is from memory of the docs); `smoke-slots.ts` proves it live. |
| 3 | Create-only semantics of `version: 0`: the doc page found by search does not spell it out. | Implemented as the plan says (`POST custom-objects` with `version: 0`; a 409 means the object exists). The unit fake models it; `smoke-slots.ts` verifies it live (F-todos). |
| 4 | The browser recipe names `mlv-doc-okafor`; the seeded doctor key is `mlv-doc-amara-okafor`. | Scripts default to `mlv-doc-amara-okafor`; the recipe text in the workstream file was not changed. |
| 5 | A claim is per `doctorKey+mode`, so a doctor can be booked remote and office at the same instant. | Followed the plan (key includes the mode). The weekly pattern is shared by both modes. Owner may want one claim per doctor and instant. |
| 6 | `listFreeSlots(doctorKey, mode, fromDate, days)`: is `fromDate` a start date or "now"? | It is "now" (default `new Date()`): day 0 = today in the clinic zone, slots earlier than `fromDate + 2 h` are hidden. |
| 7 | Slot claims are found with a `value(doctorKey=... and mode=...)` predicate and filtered by instant in memory; old claims accumulate. | Fine for the demo (a handful per doctor). A purge or a `startsAt >= now` predicate is an idea, not done. |
| 8 | Guest booking expiry length. | `expiresAt = startsAt + 7 days` (`GUEST_RETENTION_DAYS`); an expired guest booking is unreadable. Nothing purges the objects (F-missed). Guest lookups need the booking email. |
| 9 | Cancel window: "≥ 2 h before". | Exactly 2 h before is allowed; less is `CancelTooLateError`. The booking is marked `cancelled` first (versioned write), then the claim is deleted. Cancelling twice returns the cancelled booking. |
| 10 | Idempotency on `requestId`. | The booking reference is derived from the request id (`BK-` + 10 characters of a SHA-256, alphabet without 0/1/I/L/O/U), so a retry finds the same booking without an index. A claim left by a crashed attempt with the same request id is resumed. |
| 11 | `createBooking` for a time that is not an offered slot (not in the pattern, past, < 2 h). | `SlotUnavailableError`; a slot held by someone else is `SlotTakenError`. |
| 12 | Where does the `Booking` shape live? | `lib/clinical/types.ts` (pure types), re-exported by `lib/ct/bookings.ts`. Nothing added to `lib/types.ts` (workstream G's area); the client-facing view types can be added by whoever builds the pages. |
| 13 | `restrictions.test` requires `import 'server-only'` in every `lib/ct/*` file. | The pure slot maths live in `lib/clinical/slots.ts` (no server import, no SDK) so `smoke-slots.ts` (tsx, no RSC) and later UI code can share them. |
| 14 | Prescription value has no expiry field in the plan, but Jordan needs an expired RX. | Added optional `expiresAt` (ISO date) to `Prescription`; absent = no expiry. |
| 15 | Reviews: "rating statistics read through the product projection". | `getRatingStatistics(productId)` reads `reviewRatingStatistics` from `productProjections().withId().get({staged:false})`. Reviews carry no state, so they count toward statistics immediately. All seeded reviews are verified, so the "only verified" filter is covered by unit tests, not live data. The prototype's 4.9 / 312 reviews cannot be matched with 3 to 6 reviews per doctor; the real counts are shown instead. |
| 16 | Fixed `patientRef` values in seed data (`pt_8k2m4q7x`, ...) instead of random ones. | The seed must be idempotent, so the three refs are constants; they are opaque and synthetic. Real patients would get random ones at registration. |
| 17 | `SEED_PATIENT_PASSWORD` missing. | `seed` prints a notice and seeds everything except the three customers (a skip step is logged). `seed:verify` then fails "exactly three example.com patients". |
| 18 | Seed overwrite policy for Custom Objects. | Create-only; `malva-rx` and `malva-booking` are never compared (refills and status change in use); schedules, labs and credentials are compared and a difference stops the run, like other seed resources. |
| 19 | `clinical` seeding and checks are opt-in in the programmatic API (`runSeed({clinical})`, `runVerify({clinical})`), on in the CLI (`--only` turns seeding off, `--no-clinical` turns verify off). | Keeps workstream E's tests and callers unchanged. |
| 20 | `advance-order` from an order without a state. | Only the initial state (`mlv-received`) is allowed. An order in a non-`mlv-` state is refused. Same state again is a no-op. |
| 21 | Shared files touched. | `package.json` (+1 script `seed:advance`), `seed.ts` (clinical steps, `SeedOptions`), `verify.ts` (opt-in hook), `lib.ts` (`Kind` also accepts `'reviews'`), `fake-root.ts` (reviews kind, Custom Objects, `transitionState`). `lib/types.ts` untouched. No new dependencies. |
| 22 | Date library. | None: `Intl.DateTimeFormat` only (offset and wall-time maths in `lib/clinical/slots.ts`; DST gap and fold tested). |
