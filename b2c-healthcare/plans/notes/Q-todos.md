## Live checks of the build (any project with a seed and an API client)

1. **Application mode (important):** the plan (and this build) assumes Checkout in payment-only mode only authorizes and the STOREFRONT creates the order (needed for `MLV-` numbers, the prescription record and `consumeAuthorization`). The commercetools docs for the SDK describe `checkout_completed` with an order id when Checkout itself creates the order. Confirm in the Application settings that Checkout does not create the order; if it does, the storefront would find the cart already `Ordered` and `placeOrder` would return that order without `orderNumber`/line records. Record the answer in `PROJECT-FINDINGS.md`.
2. **Browser SDK messages:** the code reacts to `payment_started`, `payment_completed` / `checkout_completed` (success), `payment_cancelled`, and the error `payment_failed`. Verify these names against a live widget (they come from the docs, unverified live). The server never trusts them: it reads the Payment from the cart.
3. **Custom payment button:** the Place order button carries `data-ctc-selector="paymentButton"` so the SDK hides its own pay button and listens for clicks. Confirm it is picked up although the button lives outside the payment card, and that a click while the widget is still loading does nothing harmful.
4. **Payment on the cart:** `getAuthorization` expands `paymentInfo.payments[*]` and reads the newest payment's `Authorization` transaction (`Success` = authorized, `Failure` = declined). Confirm Checkout attaches the Payment to the cart (not only to the order) at authorization time and that the transaction `amount` equals `taxedPrice.totalGross`.
5. **Shipping method matching:** `GET shipping-methods/matching-cart?cartId=` for a cart with address `{country: US, state: NY}` returns `mlv-standard` and `mlv-same-day` (zone `mlv-same-day-states`), with `zoneRates[].shippingRates[].isMatching`. Confirm the price shown (0 / 500) is the matching rate, and that for `state: CA` only standard comes back.
6. **Cart creation with a country-only address:** O creates carts with `shippingAddress {country}` and `mlv-standard`. Confirm the platform keeps the method and tax after `setShippingAddress` with a full address; checkout also re-selects standard when the method no longer matches.
7. **Order from cart:** `POST /orders` with `{cart: {typeId: 'cart', id}, version, orderNumber, state: {typeId: 'state', key: 'mlv-received'}}`. Confirm the state is accepted as initial and that `orderNumber` collisions answer 400 `DuplicateField`. Check the line item custom fields `dispensedQty`, `authorizationParams`, `suppliedLots` arrive on the order lines.
8. **Seed:** `npm run seed` again so `mlv-rx-line` gains `dispensedQty`, `authorizationParams`, `suppliedLots` (String). If the seed only creates missing types, add the three field definitions in the Merchant Center (or extend the seed, workstream E). Also check whether a String custom field accepts the length of `suppliedLots` for a line filled from several lots (F-08 writes it).
9. **Scopes:** the storefront client needs `manage_orders` (carts and orders), `manage_payments` (read payments), `manage_key_value_documents` (counter, attempt locks, rx, ledger), `manage_sessions`, and `manage_checkout_payment_intents` (release). The new scope line is documented in `.env.example`.
10. **Counter:** after the first order `malva-counter/order-number` holds `{ "next": 2 }`; two parallel placements (two browsers) never share a number. `malva-order-attempt` has one entry per attempt (`<cartId>_<version>`); entries are never deleted after success (they are the idempotency record). Decide a retention rule (IDEAS).
11. **Release:** with a real authorization, force a failure (e.g. add an unservable line after paying) and confirm `cancelPayment` voids the authorization in Stripe (`CancelAuthorization` transaction on the Payment).
12. **Same-day cut-off in the browser:** with `SAME_DAY_NOW_OVERRIDE=2026-10-08T09:00:00-04:00` same-day is offered for NY; with `...T15:00:00-04:00` it is withdrawn and the note appears; a same-day order started at 13:59 and placed at 14:01 is refused with "No delivery option is available".
13. 390 px and 900 px layouts of `/checkout` (class-level only so far; no browser available): summary stacks under the cards below the `nav` breakpoint, sticky at 96 px above it; focus ring on the radio cards and the Place order button.
