# Workstream W: questions and the defaults chosen

| # | Question | Default chosen |
| --- | --- | --- |
| 1 | Carry the cart over or start empty on a region switch with a cart? | Start empty (as the plan says). `POST /api/locale` answers `cartCleared: true` when the session had a `cartId` and the write dropped it (G's `withRegion` does that on a currency change). The client empties the cart SWR keys and shows the toast "Your cart was emptied because prices are in a different currency. You can add your prescription lines again." Lines are not listed one by one (nothing is carried, so nothing is "left behind" selectively). |
| 2 | The old cart stays Active in commercetools; O's `fetchActiveCart` picked "the newest Active cart of the customer", which could be the old-currency one (O-missed). | `fetchActiveCart` takes the visitor's currency: a cart named by `cartId` must have that `totalPrice.currencyCode`, and the customer lookup adds `totalPrice(currencyCode=:currency)`. `getCartSummary`, `removeLine` (new optional last argument) and `getCartValidated`/`getOrCreateCart` (via `ctx.currency`) all pass it; the two cart Route Handlers pass the session currency. The old cart is never deleted or modified; it is found again if the patient switches back. Without the currency argument behaviour is unchanged. |
| 3 | Where is the switcher's region list resolved? The header is a synchronous server component. | `app/[locale]/layout.tsx` awaits `getSwitchableRegions(locale)` (`lib/regions.ts`) and passes `regions` down `Header` -> `HeaderClient` -> `RegionSwitcher`. With one `COUNTRY_CONFIG` entry it returns `[]` without calling the project; a failing project read also returns `[]` (no switcher rather than a broken layout). The component itself renders nothing for fewer than two regions and mounts no router hooks then. |
| 4 | The task says navigate "with `getPathname`". | The hook calls next-intl's `router.replace(pathname + search, { locale })` from `@/i18n/routing` (it uses `getPathname` internally), then `router.refresh()`. A soft navigation keeps the toast provider mounted so the "cart emptied" message stays visible; a hard navigation with `getPathname` would drop it. `POST /api/locale` happens first, so the new request already carries the new session. The query string is kept. |
| 5 | Which "not sellable" shape? | `sellableInRegion?: boolean` on `Medication` and `DoctorCard`, set by the mappers (medication: no pack price in the currency; doctor: no fee on any mode channel in the currency). Optional so no existing fixture breaks; absent means sellable, only `false` is acted on. The doctor profile page shows the "Not available in this region" card instead of the booking panel. Search excludes such products through a currency filter ANDed into every request (`buildSellableFilter`); G's test that expected no query for an unrestricted search was updated. |
| 6 | The spec scenario "Product not sellable in the new region" speaks of cart lines. | Because the cart is emptied on a currency change, no line is carried into the new region. The scenario is covered by the read flag, the page notice and the search exclusion (the plan's design). If carrying lines over is chosen later, `checkLines`-style flags per line would be needed. |
| 7 | Switcher on mobile. | The select is hidden under the `nav` breakpoint like the search link (header space). It is not in `MobileMenu` (H's file, kept out of scope). Only relevant once a second region exists. |
| 8 | Label text. | "United States, English (USD)" built from `Intl.DisplayNames` in the page language; the control is a native `select` with the accessible name "Region and language". |
