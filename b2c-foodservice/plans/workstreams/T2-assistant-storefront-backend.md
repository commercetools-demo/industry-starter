## 2. Goal and scope

**Goal.** The assistant keeps its chat, cards, prompts, trust gates and model. Its `StorefrontBackend` is now implemented with the storefront's existing server modules (`lib/ct/*`, `lib/mappers/*`), not with the Shopper MCP. The assistant's cart **is** the shopper's bag.

**What stays exactly as it is (do not touch):** `lib/agent/common/**`, `lib/agent/shopping/**` (prompt, tools, gates, grounding, enrichment, executor, serializers), `lib/agent/runtime/**`, `lib/agent/store/**`, `lib/agent/host/**`, `lib/agent/http/**`, the turn, session and card routes, the panel, provider, launcher and the cards (except the checkout card, U-10). The static prompt and tool bytes are frozen: `lib/agent/shopping/prompt.test.ts` pins the hash. If that test fails you changed prompt bytes by accident; undo it.

**What is new**
- `lib/ct/assistant-backend.ts`: a `StorefrontBackend` over `lib/ct/*`.
- `lib/mappers/assistant.ts`: pure mappers from storefront types to the agent's types.
- The assistant writes straight into the shopper's bag. No second cart, no "adopt".

**What is deleted** (U-11): `lib/agent/backend/shopper-mcp/**`, `lib/ct/adopt-cart.ts`, `app/api/assistant/adopt-cart/`, `hooks/useAdoptCart.ts`, `scripts/shopper-mcp-probe.mjs`, the `@modelcontextprotocol/sdk` dependency, every `SHOPPER_MCP_*` name.

**Still true (must not regress):** the assistant never places an order; it has no ordering method. The model supplies ids and prose only; every displayed fact is joined server-side. Cart writes need provenance (a card click keeps caps and the options hold, not provenance). Orders only for the signed-in shopper's own orders.

**Out of scope:** collection in store, subscriptions, discount codes, shipping and tax estimates. The assistant adds **delivery** lines only (`fulfilment: 'delivery'`).

## 3. Design decisions (binding, read them before coding)

1. **Where the code lives.** `lib/agent/**` may not import `lib/ct`, `lib/mappers`, `lib/session` or `@commercetools/*` (lint). So the backend is `lib/ct/assistant-backend.ts` (it may import `@/lib/agent/...` types, as `lib/ct/assistant-orders.ts` already does) and the mappers are `lib/mappers/assistant.ts`. The route layer builds the backend and hands it to the agent, as `lib/agent/service.ts` does today with `createAssistantBackend`.
2. **Ids.** Keep the id scheme the prompt and gates already know: a **family** id is `fam:<defaultSku>` (the product's `defaultSku`, so it can be loaded with `loadProductPage(sku, locale)`), every other id is a **SKU**. A product with more than one variant is a family (its `options` come from the product's selectors); each of its variants is a purchasable record with `id = sku` and `variantOf = fam:<defaultSku>`. A product with exactly one variant is a plain product with `id = sku`. The cart refuses `fam:` ids (already enforced by `gates.ts`). Move `ids.ts` out of the MCP folder (U-01); its decode never throws.
3. **Money.** The storefront holds integer minor units (`Money` in `lib/types.ts`). The agent holds major-unit floats. Convert in exactly one place, `lib/agent/shopping/money.ts` (moved from the MCP folder in U-01, uses Intl fraction digits). A figure the platform cannot supply is **absent**, never `0`.
4. **The bag is the cart.** Cart reads and writes go through `lib/ct/cart.ts` (`getCartView`, `addLine`, `changeQuantity`, `removeLine`) with the shopper's own `Session`, so ownership, brand channel, price refresh and optimistic retry (`updateWithRetry`) are already done. Never call `apiRoot` for carts yourself.
5. **Cookie constraint (the one hard part).** A Route Handler cannot set a cookie after a streamed body has started. A first add normally creates the cart and a new `cartId` must reach the cookie. **Default (Q-T2-1): create the bag when the assistant session starts** (`POST /api/assistant/session` is a normal response, it can set the cookie) if the shopper has no active bag. If the bag is lost during a turn (deleted or no longer Active), the cart tool answers `Unavailable` with a sentence telling the shopper to reload the page, and logs the tool name only. Do not try to set cookies from the stream.
6. **Search across both brands.** The session has no brand and the shopper may switch brand mid-chat. Call search with no `brand` in the context (all products). `addLine` already decides the line's brand on the server from the product, never from the request.
7. **Locale and market.** Every call uses the session's market (`country`, `currency`, `locale` from the principal), never a body field.
8. **Not-orderable.** Before an add, check the online stock (`getInventoryDetail` in `lib/ct/inventory.ts`). Out of stock throws `Unavailable` whose message names **ids only** (the variant id and the in-stock sibling ids). Titles are catalogue text and stay inside fences.
9. **Orders.** `listOrders(customerId, ...)` and `getCustomerOrderByNumber` / `getCustomerOrderById` are customer-scoped in the query; unknown and foreign are the same `null`. A guest gets `SignInRequired`. The order card's "View order" link is `/<brand>/<locale>/account/orders/<orderNumber>` (a same-origin path; the card already validates it).
10. **No new commercetools scopes, no new env vars.** The assistant uses the storefront's existing API client.

## 6. Risks to watch

- **Cookie.** Do not set cookies from the stream. If the bag was lost, the tool says reload. This is rare and documented.
- **`getCartView` cost.** It reads prices and shipping on every call. If a turn feels slow, measure before optimising; a lighter read (`getCartForSession` plus the mapper) can replace it for the tool results, but the checkout card total must still come from the full view.
- **Search quality.** The shop's Product Search is keyword based; the model must search again with other words when results are thin. That is prompt behaviour, which is frozen: do not edit prompts to compensate.
- **Prompt bytes.** If `prompt.test.ts` fails, revert your change to `lib/agent/shopping/**`.
- **Both brands.** Malva Drinks products have bare numeric SKUs and a brand inventory channel; `addLine` handles the channel. Test one drinks SKU by hand in U-13.
